# HD-2D にする方針（10/31。まだ作らない）

真上から見下ろす盤面に、角度をつけて**奥行き**を出す。3D の模型にはしない（オーナー 10/31「3D というより、奥行きを付けたい」）。
絵は平らな画像のまま。盤を傾けて奥を遠くに見せ、キャラ・村・トロッコは今の駒を立て（ビルボード）、山は高く見せる。
**操作はそのまま、見た目だけ変える**（オーナー 10/31）。

```
 変えない ── ルール（rules.js）・数値（balance.js）・テストの結果
 変えない ── 操作（マスを押す・十字の向き・魔法・待機・右下のボタン）
 変える  ── 描き方（ui.js の盤面・style.css）だけ
```

## 方針

1. **変えるのは見た目だけ。** rules.js・balance.js に触れない。`node tests/run.js`・`tests/scenarios.js`・`tests/snapshot.js` の結果は1文字も変わらない（例外は下の「トロッコ」の名前だけ）。
2. **操作はそのまま。** 画面の ↑ は盤面の奥。十字の向きと盤面の向きがずれない。
3. **見た目で、ルールにないことを約束しない**（2章「魔法を現実に存在させる。信頼」）。高さはルールにある分だけ見せる（丘・山・頂上）。「山の陰に隠れられそう」に見せない。
4. **読みやすさが先、雰囲気はその次**（3章）。予告・予測・向きは今と同じだけ読める。
5. **今の真上の見た目を残す。** 展示は奥行き、開発は両方を切り替えて試せる（決まり 10/31）。展示を奥行きにするのは、できあがってから（決まり 10/31。下の「切り替え」）。
6. **素の HTML / CSS / JS・file:// で動く**（11章）を守る。
7. **奥行きは、3D の模型ではなく舞台。** カメラは回さない。光の計算や立体のモデルは作らない。

## 作り方（Claude のおすすめ）

- 今の盤面は「マスごとの div」。これを傾けて奥行きを付け、駒は起こして立てる（ビルボード）。
- 押す所・予告や予測の印・テストの仕組みがそのまま使える。作り直しが一番小さい。

## Claude が決めて進める（見て違えば直す）

- カメラは固定。手前から見て、↑ が奥。回さない（回すと十字の向きとずれる）。
- 盤面の印は2つに分ける: 床に貼る（形・予告の枠・道筋）と、立てる札（ダメージ・あと一手・構えの番号）。
- 奥の駒が山に隠れるときは、山を透かすか駒の輪郭を出す。
- エディット（作る側）は真上のまま。
- 高さ: 空きは平ら、丘は低い台（崖つき）。山はつながったかたまりを一つの山にして、頂上から山のふちまでまっすぐな山肌で下ろす（オーナー 10/31「斜めにまっすぐ。イメージは一つの山」で決まり）。頂上はルールの斜面 `mountainSlopes` と同じマス。山の足もとは通れないマスにぴったり合わせる（通れるマスまで山に見せない）。
- トロッコの名前: 「馬車」の言葉は rules.js（23か所、出来事の文）・ui.js・balance.js・stages_io.js・style.css・テストにある。変えるのは言葉だけ。スナップショットは言葉の分だけ変わるので、言葉以外が同じことを確かめてから記録し直す。
- 絵が入る前でも動くように、画像がなければ今の駒をそのまま立てる。
- 画像は魔法ごとに1枚（村・トロッコも1枚ずつ）。盤面の駒と立ち絵は同じ1枚を使い、あとで駒用の絵を別に入れれば駒だけ差し替わる形にする。置き場所と名前は、作る前に一覧で見せる。
- 画像はフォルダに入れる形（オーナーは、できてから決まった名前で入れるだけ。ないものは仮置きのまま動く）。公開（tools/publish.js）は今 index.html が読むファイルしか拾わないので、作るときにそのフォルダも公開に含めるようにする。
