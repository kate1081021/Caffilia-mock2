## 0. 進め方のルール

- **最初に、今あるファイル一式を `v2/` フォルダにコピーする。** 比べられるように残すため。`.claude/` と `v1/` はコピーしない。
- **質問しない。** あいまいな所は、この文書の意図に沿う一番シンプルな解釈を選ぶ。選んだ解釈は `DECISIONS.md` に「敵:」を付けて1行ずつ追記する。
- **`PROGRESS.md` を作り直す。** 下の「作業手順」をチェックリストにし、1ステップ終わるごとに更新する。
- 詰まったら飛ばす。1つのステップで30分以上進まないときは、状況を `PROGRESS.md` に書いて次へ進む。
- ファイル構成と分け方（ルールは `rules.js`、画面は `ui.js`、数値は `balance.js`）、file:// で動くこと、外部ライブラリを使わないことは今までどおり。
- 今あるシナジー・小さなシナジー・試し中の切り替えは、壊さずにそのまま動くこと。
- 終わったら `REPORT.md` を書き直して終了する。

## 1. ねらい

敵の狙いが先に見えて、それを潰すか、利用する。気持ちいいのは次の2つ。

- **敵の魔法が火種になる。** 敵の火の着弾点に森を足しておくと、敵の火で燃え広がりが起き、敵が自分の魔法に巻き込まれる。
- **敵が罠に踏み込む。** 敵が進む道に、こちらが作った自然が待っている。

迷ったときの基準は2つ。

- **敵の手は、予告を決めた時点の盤面では筋が通っていること。** 敵が自分の魔法に巻き込まれるのは、予告のあとでこちらが盤面を変えたときだけにする。予告の時点で自分や仲間を巻き込む手を選ぶ敵は、おバカに見える。
- **賢さより読めること。** 同じ盤面なら必ず同じ手を選ぶ。

## 2. 手番の流れ

イントゥ・ザ・ブリーチと同じく「敵が動いて狙いを出す → 味方が動く → 敵の魔法が発動」の順にする。

1. **敵の移動と予告**: 敵が決まった順に1体ずつ動き、次に撃つ魔法の予告を出す。
2. **味方の手番**: 今までどおり（移動 → 向き → 撃つ／待機）。
3. **敵の魔法の発動**: 予告した魔法が、敵の順に1つずつ発動する。
4. **ターン終了処理**: 燃え移り・小さな炎が消える・風がやむ・渦が解ける・花びらが散る、など今までどおり。
5. 1に戻る。

- 戦闘は「1. 敵の移動と予告」が終わった状態から始まる。味方は最初の手番から敵の予告を見られる。
- 発動をターン終了処理より先にするのは、味方がそのターンに作った一時的な自然（風・小さな炎など）に、敵の魔法が当たれるようにするため。たとえば味方の風に敵の火が当たれば、火の渦になる。

## 3. 予告

- **予告は、敵の位置と向きに固定する。** 敵は自由に狙えない。発動するときは、その瞬間に敵がいるマスと向いている向きから、予告した魔法を撃つ。風で押されて敵の位置が変わったら、形も一緒に動く。盤の外に出たマスは無視する。
- **予告したあと、敵は発動まで動かない。** 自分で移動も向きの変更もしない（押されて動くことはある）。
- 発動の前に倒れた敵の予告は消える。泥沼にはまっていても、発動は起きる。
- 発動の結果は、**発動の瞬間の盤面**で決まる。予告のあとで味方が盤面を変えれば、結果も変わる。

### 予告の見せ方

- 予告中の敵ごとに、形のマスと向きを常に表示する。
- **形のマスだけでなく、「今の盤面で発動したら何が起きるか」まで表示する**（変わるマス、起きるシナジー、誰に何ダメージ）。盤面が変わるたびに計算し直す。
- 複数の敵の予告は、敵の順に発動したものとして続けて計算する（前の敵の結果が、次の敵の盤面になる）。
- **味方が撃つ前の予測を出しているあいだは、撃ったあとの盤面で敵の予告の結果も計算し直して見せる。** 「ここに森を足せば、敵の火で敵ごと燃える」が、撃つ前に分かるようにするため。
- 今の「敵の予告（ターン終了を試しに動かした結果）」の表示は、この予告に置き換える。

## 4. 敵の移動と予告の決め方

骨組みは全部の敵で共通。個性は「5. 敵の個性」の項目だけで出す。

### 共通

- 移動は最大2マス。**通れないマスは避けて進む**（他のユニットのマスも通れない）。泥沼にはまっている敵は動けず、今の位置で予告だけ決める。
- 今の位置から行けるマス（今の位置も含む）と4つの向きの組み合わせを全部試し、それぞれ「今の盤面で撃ったら何が起きるか」を計算する。
- **その時点の盤面で、自分や他の敵がダメージを受ける組み合わせは選ばない。** そういう組み合わせしかないときは、その場で、自分も仲間も巻き込まない向きを選ぶ（どの向きも巻き込むなら、一番近い味方の方を向く）。
- 残った組み合わせから、敵の「狙い」（5章）で1つ選ぶ。
- 同点なら「移動が短い → 移動先は上・右・下・左の順に広げた幅優先探索で先に見つかった方 → 向きは上・右・下・左」の順で決める。

### 狙う相手がいないとき

- 狙いで点が付く組み合わせが1つもないときは、一番近い味方（避けるマスを避けた道のり）へ向かって最大2マス進み、その味方の方を向いて予告する（縦横で差の大きい方。同じなら縦）。
- 道がなければ、その場で一番近い味方の方を向いて予告する。

## 5. 敵の個性

敵ごとに次の4つを持たせる。初期値は `balance.js` に置き、エディットで敵ごとに変えられるようにする。

| 項目 | 選べるもの | 初期値 |
|---|---|---|
| 魔法 | 魔法の一覧から1つ（敵だけの魔法も含む） | 火 |
| 狙い | 人数 ／ 近い人 ／ 自然 | 人数 |
| 避ける | 通れない所だけ ／ 危ない所も | 通れない所だけ |
| 越える | なし ／ 川を渡る | なし |

- **狙い**
  - 人数: ダメージを受ける味方の数が多い組み合わせ。同じなら合計ダメージが大きい方。
  - 近い人: 一番近い味方に当たる組み合わせ。当たらなければ近づく（4章の「狙う相手がいないとき」と同じ）。
  - 自然: 変わる自然のマスが多い組み合わせ（空き以外のマスが別のものになる数）。味方が作った盤面を崩しに来る敵。
- **避ける**
  - 通れない所だけ: 炎・小さな炎・泥沼などは、ふつうの通れるマスとして扱う。
  - 危ない所も: 炎・小さな炎・泥沼・溶岩を、通れないマスと同じように避ける。移動先にもしない。
- **越える**
  - 川を渡る: 川・水たまりを通れるマスとして扱う（凍った川は誰でも通れるので変わらない）。
- 個性は、敵の見た目で分かるようにする（狙い・避ける・越えるを小さな印か文字で）。

## 6. 敵だけの魔法

- `balance.js` に「敵だけの魔法」の一覧を置く。ここに入れた魔法は、味方のエディットの選択肢に出さない。
- 最初は空にしておき、初期シナリオの中で敵にだけ持たせる形で試す（7章）。
- 敵だけの魔法も、味方と同じ形・向き・進み方・シナジーのルールで動く。

## 7. 初期シナリオ

今あるシナリオは残し、次の3つを足す。盤面の大きさと配置は、意図が伝わるように決めてよい。

1. **「敵の火を使う」**: 味方 草・水・風、敵2体（火・狙い人数）。敵の火の予告先に森を足すと、敵の火で燃え広がりが起きて敵が巻き込まれる。水で消す手もある。
2. **「罠に踏み込む」**: 味方 草・火・土、敵2体（土）。1体は「避ける: 通れない所だけ」、もう1体は「危ない所も」。避けない敵は燃える森を踏んで進み、避ける敵は泥沼や炎で道を絞られる。
3. **「敵だけの雷」**: 味方 土・水・風、敵2体（雷・狙い人数）。雷を「敵だけの魔法」に入れる。こちらの川に敵の雷が落ちれば、感電で水のそばの敵が巻き込まれる。

## 8. 作業手順（PROGRESS.md にそのまま写す）

1. `v2/` にバックアップ
2. `balance.js` と状態の形に、敵の個性・予告・敵だけの魔法を足す
3. 手番の流れを「敵の移動と予告 → 味方 → 発動 → ターン終了処理」に組み替える
4. 敵の移動と予告の決め方（4章）
5. 敵の個性（5章）と敵だけの魔法（6章）
6. 予告の発動（位置と向きに固定、押されたら形も動く、倒れたら消える）
7. テストを足して全部通す（下記）
8. 画面: 予告の表示・発動したら何が起きるかの表示・味方の予測中の計算し直し・個性の印
9. 画面: エディット（個性の変更）・保存と JSON に個性を含める・初期シナリオ
10. 最後の確認
11. `REPORT.md`

### テストに入れるもの

- 戦闘の最初に、敵の予告がすでに出ている
- 予告した敵は、味方の手番のあいだ自分では動かない
- 予告のあとで味方が森を足すと、発動の結果が燃え広がりに変わる
- 風で押された敵は、押された先から同じ向きで撃つ
- 倒れた敵の予告は発動しない
- 予告を決める時点で、自分や他の敵を巻き込む組み合わせは選ばれない
- 狙い（人数・近い人・自然）ごとに、期待どおりの組み合わせが選ばれる
- 「危ない所も避ける」敵は、炎・泥沼を通らず移動先にもしない／「通れない所だけ」の敵は通る
- 「川を渡る」敵は川の上を進める
- 敵だけの魔法は、味方の選択肢に出ない
- 発動はターン終了処理より先（味方の風に敵の火が当たると火の渦になる）
- 同じ盤面からは、何度やっても同じ予告になる

## 9. 最後の確認

- `node tests/run.js` が全部通る。
- `tests/scenarios.js` に、次の流れを `rules.js` だけで最初から最後まで動かす場面を足す。
  1. 「敵の火を使う」: 敵の火の予告先に草で森 → 発動で燃え広がり → 敵が巻き込まれる
  2. 「罠に踏み込む」: 避けない敵が森を踏む → 火で燃やす／避ける敵が泥沼で道を絞られる
  3. 「敵だけの雷」: 水で川 → 敵の雷が川に落ちて感電 → 水のそばの敵が巻き込まれる
- 今あるデモ（スーパープレイ）は、新しい手番の流れで勝てるか確かめる。勝てなくなったものは、外すか手順を探し直し、どちらにしたかを `DECISIONS.md` に書く。
- すべての .js に `node --check` をかける。
- 画面は内蔵ブラウザで、各初期シナリオの予告の表示と、味方の予測中に予告の結果が変わる様子を確かめる。

  - **敵の手が読めない場面がないか。** なぜその手を選んだのかが、狙いと個性から説明できないもの
