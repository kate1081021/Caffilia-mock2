# LAB_00 — 試作ラボの土台（最初に1回だけ）

これまでの話し合いで出た「やりたいけど、まだ試せていないアイデア」を、モックの中で1つずつ動かせるようにする。
オーナーが遊んで **面白い／面白くない** を判定し、本実装に使うかを決めるための場所（**試作ラボ**）を作る。

このファイルでは、ラボの仕組み（切り替え・ラボ用シナリオ・判定パネル・書き出し・報告）だけを作る。
中身の案はカテゴリごとに `LAB_A`〜`LAB_K` に分けてある。**1ファイル＝1回の作業**として、下の順番で進める。

今回は正解を作る回ではなく、**判定できる状態を作る回**。どの案も小さく、すぐ切れる形で入れる。

---

## 0. 進め方のルール

- **質問しない。止まらない。** あいまいな所は、案の意図に沿う一番シンプルな解釈を選ぶ。選んだことは `DECISIONS.md` に「ラボ:」として1行ずつ書く。
- **最初に `LAB_PROGRESS.md` を作る。** 案ごとの状態（作った／既存／飛ばした（理由））をここに書き、1つ終わるごとに更新する。会話が長くなって前を忘れたら、まず `LAB_PROGRESS.md` と、このファイルの「大前提」を読み直してから続ける。
- **詰まったら飛ばす。** 1つの案で30分以上進まないときは、何が重いかを `LAB_PROGRESS.md` に書いて次の案へ。全部を止めない。
- 外部ライブラリ・ビルド・ネットは使わない。`index.html` を開けば動く（file://）まま。テストは node だけ。

## 1. 最初に読むもの

- `CLAUDE.md`（判断の基準）。ラボの案には基準から外れるものも混ざっている（試すのが目的なので、外れていても作る）。外れる案は、判定パネルのカードに「CLAUDE.md の〇〇から外れる」と書く。
- `DECISIONS.md`・`SYNERGIES.md`・`REPORT.md`・`NOTES.md`（今の標準）
- 読んだら、`LAB_A`〜`LAB_K` の案のうち **すでにモックにあるもの** を洗い出して `LAB_PROGRESS.md` に書く。
  - すでにあるものは作り直さない。判定パネルに「既存」として登録し、切り替えがあればそれを使い、ラボ用シナリオだけ作る。
  - 特に `IMPROVE_ideal`（山に登れる・歩いても滑る・森に隠れる・波の見せ方）と `IMPROVE_grow`（二段で育つ・縮尺の見本・大きな1枚の絵）が入っているかを確かめる。
  - 展示（10/17）のために入れたルール（十字の山、水は高い所から低い所へ流れる、など）があれば、それを今の標準として扱う。
  - LAB ファイルに書いていなくても、**モックにあってオーナーがまだ判定していない切り替え**（縮尺の見本、育つ、山に登れる、小さなシナジー、桜吹雪の起こし方 など）は、判定パネルの「既存」のまとまりに並べる。今あるものも、ここで一度に判定できるように。
- **二段（育つ）が要る案は `IMPROVE_grow` が入っていることが前提。** 入っていなければ、`.claude/` に `IMPROVE_grow.md` があれば先にそれを済ませる。なければ、二段が要る案は飛ばして書き残す。

## 2. 大前提（全部のラボの案に共通）

1. **展示を壊さない。**
   - git が使えるなら `lab` ブランチを作り（あれば切り替え）、その上だけで作業する。main には戻さない・マージしない。展示用の直しは、オーナーが main で続ける。
   - 公開するときは、固定版を `lab-MMDD` の名前で出すだけ（`node tools/publish.js lab-MMDD`）。**`latest` は絶対に更新しない**（展示用の最新版が上書きされるため）。
   - 展示用のステージ・シナリオ・デモ・チュートリアルには手を入れない。
2. **全部オフなら今と同じ。** ラボの案はすべて `balance.js` の `lab` の中に、1つずつ切り替え（true/false）と数値で置く。初期値はすべてオフ。オフのとき `node tests/run.js`・`node tests/scenarios.js` の結果が1つも変わらないこと。
3. **法則に例外を作らない。** 案は敵にも味方にも同じく効く（案の中で「敵だけ」と書いたものを除く）。
4. **撃つ前に読める。** 案で起きることは、今の予測・敵の予告にそのまま出る。出せないときは、その旨をカードに書く。
5. **作り込まない。** 数値・形・配置は全部【仮】。迷ったら一番シンプルな形を選ぶ。
6. **盤面に置くものは、全部魔法で作れるもの**（村・馬車・宝などお題の置きものを除く）。

## 3. 作るもの

### 3-1. 切り替えの置き方

- `balance.js` に `lab: { ... }` を足す。キーは案の番号（`A1`・`C3` など）。値は `{ on: false, ...その案の数値 }`。
- 調整パネル（`tune.js`）に「ラボ」のまとまりとして自動で並ぶようにする。ラベルは案の名前（番号ではなく）。
- ルール側は `BALANCE.lab.A1.on` を見るだけにする。案ごとの処理は関数に分ける（`lab_rules.js` に分けてもよい）。あとで本実装に移すとき・捨てるときに、1か所で済むように。
- 案どうしの依存（例: 「雪崩」は氷の魔法が要る、「囮の森」は敵の欲が要る）は、案の定義に `needs: ['D1']` のように書く。ラボでその案を選ぶと、`needs` も一緒にオンになる。
- `needs` が、まだ作っていない（後のファイルの）案を指しているときは、その案は後回しにする。`LAB_PROGRESS.md` に「後回し: 〇〇待ち」と書き、`needs` の案を作ったファイルの作業の最後に戻って作る。

### 3-2. ラボ用シナリオ

- 案ごとに、その案だけが分かる小さなシナリオを1つ作る。シナリオ一覧に「ラボ」のまとまりを足し、さらにカテゴリごとに分ける。
- シナリオを読み込むと、その案と `needs` だけがオンになり、ほかのラボの案はオフに戻る。
- 盤面は小さめ（6×6〜8×8）。敵は基本、動いて予告する敵にする（案が敵に関わらないときは止めてよい）。
- **1ターン目から、その案が起きる一手が見つけられる配置にする。** 見つけるまでに何ターンもかかるシナリオにしない。
- できれば **スーパープレイ（デモ）を1つ**。その案のいちばん良い瞬間が起きる手順。探索で見つからなければ手で組む。それでも組めなければ、なしでよい（カードにそう書く）。
- 案の中に「組み合わせシナリオ」があるものは、それも作る（複数の案を一緒にオンにした盤面）。

### 3-3. 判定パネル（いちばん大事）

上のバーに「ラボ」ボタン。押すと左から開く（調整パネルと同じ作り）。

**一覧**
- カテゴリ（A〜K の名前）ごとに、案の名前と判定の印（未・面白い・微妙・面白くない・分からない）。
- カテゴリの見出しに「判定済み N / 全 M」。
- 「既存」「デモあり」「CLAUDE.md から外れる」の小さな印。

**カード**（案を選ぶと出る）
- 名前と、ひとこと説明（何をすると何が起きるか、1〜2行）
- 試し方（このシナリオで最初にやってみる手、2〜3行）
- 判定の問い（案ごとに2〜3個。各 LAB ファイルの「問い」をそのまま）
- ボタン: 「このシナリオで試す」「オフでくらべる」「デモを見る」
- 判定: 面白い／微妙／面白くない／分からない（1つ選ぶ）
- 本実装に: 使う／直して使う／使わない／まだ（1つ選ぶ）
- メモ（自由に書ける）
- いちばん下に小さく: どこから来た案か（日付と元の言葉。各 LAB ファイルの「元」）

**くらべる**
- 「オフでくらべる」は、同じ盤面のまま、その案だけオフにして最初からやり直す。もう一度押すとオンに戻る。
- 今どちらで遊んでいるかを、上のバーに大きく出す（例:「ラボ: 丘と山　オン」）。

**保存**
- 判定とメモは localStorage に保存する（キー `cafilia-lab-judge`）。読み書きは try/catch で包む。使えない環境では、その旨を出して、書き出しだけで使えるようにする。

**カードの中身**は `lab_cards.js` にデータとしてまとめる（名前・説明・試し方・問い・元・シナリオ・デモ・needs・既存かどうか）。各 LAB ファイルを読んで、Claude Code が書き起こす。

### 3-4. 書き出しと読み込み

「判定を書き出す」で、次の形の Markdown をテキストで出す（コピーボタン付き）。オーナーがそのままチャットに貼れる形にする。

```
# ラボ判定（2026-10-xx）

## A 地形
- 丘と山: 面白い ／ 本実装に: 使う
  メモ: …
- 森は盾: 微妙 ／ 本実装に: 直して使う
  メモ: …

## 未判定
- 歩いても滑る（A 地形）
- …
```

「読み込む」で、書き出したテキストを貼ると判定とメモが戻る。

### 3-5. 報告

- `LAB_PROGRESS.md`: 案ごとの状態（作った／既存／飛ばした（理由））。
- `LAB_REPORT.md`: 案ごとに数行。作ってみて気づいたこと（違和感・思ったより面白そうな所・ほかの案とぶつかる所）と、測れたら下の数字。**遠慮なく。ただし褒め言葉より事実を書く**（オーナーの判定の邪魔をしないため）。
- `DECISIONS.md`: 「ラボ:」で決めたこと。

### 3-6. 共通の物差し（測れる案だけ。重ければ飛ばす）

`tests/playtest.js` か探索で、案のオン・オフをそのシナリオでくらべる。

- 決め手が初めて敵に入ったターン
- 敵から3マス以上離れたマスに自然を作った手の割合（関係ないところに撃つ）
- 1発で変わったマスの数の平均と最大（一気に変わる）
- 敵の魔法が材料になった決め手の回数（敵を利用する）
- 決め手の前と後で、通れるマスの数がどれだけ変わったか（局面が変わったか）
- 味方が倒れた数

## 4. 判定の問い（全部の案に共通。判定パネルの一番上に常に出す）

オーナーの狙う体験と判断の基準から作ったもの。

- 想像どおりに起きたか（「〇〇があるところに、△△が来たから、□□になった」と一言で言えるか）
- 4つの体験のどれかが濃くなったか: **関係ないところに撃った一手が勝ちにつながる／敵を妨害して罠にはめる／敵を利用する／見ているだけで楽しい**
- 難しいのはいいが、分からなくなっていないか
- カフィーリアらしいか（着弾点は選べない、魔法の形、法則に例外がない、カッコいい）
- 手が止まって考える場面が生まれたか

## 5. カテゴリと進める順番

この順に1ファイルずつ進める（オーナーの今の悩みに近い順）。各ファイルの中は **★（先に試す）→ ☆（余力があれば）** の順。時間が足りなければ☆を飛ばして `LAB_PROGRESS.md` に残す。

## 6. 終わったら（このファイルの作業）

- ラボの仕組みが動くことを、仮の案1つ（`LAB_C` の最初の案でよい）で確かめる: シナリオを読み込む → オンで遊ぶ → オフでくらべる → 判定してメモを書く → 書き出す → 判定を全部消す → 読み込んで戻る。
- 内蔵ブラウザで、判定パネルの開け閉め・カードの表示・書き出しを確かめる。コンソールエラーなし。
- `node tests/run.js`・`node tests/scenarios.js` が今までどおり全部通る。
- `LAB_PROGRESS.md` に、既存だった案の一覧を書いておく。

## 7. 試さないもの（話し合いで外したもの）

カードにも出さない。オーナーが外すと決めたものを、ラボで蒸し返さないため。

- 勝利の系譜を見せる／動いたら最後の一歩の向きを向く／留まると1マス遠くへ届く／起こし役の形を1マス離す（10/7 外した）
- 時間のブレーキ（植えたばかりの森は弱い、育つまで待つ、変わったばかりの自然はそのターン変わらない）（10/6「今ではない」）
- 超常は1戦闘に1回まで（決まりごとで縛るので「例外を作らない」とぶつかる）
- 確率で起きる効果（読めない）／敵が発動の直前にもう一度動く（予告が読めない）
- 炎が大火になって酸欠で消える、濡れた森、風を風で竜巻、川に風で渦、炎に闇で鬼火（10/4・10/5 判断ずみ）
- 属性ではなく色で分ける（10/3 属性のほうが分かりやすいと判断）
- 人のステータスだけに効くシナジー（風邪など）、アウトゲームのキャラ解放

## 8. やらないこと

- 展示用のステージ・シナリオ・デモに触る、`latest` を公開する
- 今の標準の数値を変える（案の中で変えるものは、その案の切り替えの中だけで）
- 案どうしを組み合わせた調整・最適化（組み合わせはオーナーが調整パネルで遊ぶ）
