## 二つめ：チュートリアルと本編の違い

### 処理は同じ

チュートリアルも本編も、rules.js の同じ `act`（移動して撃つ）・`endTurn`（ターン終了）・`shoot`（魔法）を通る。チュートリアル専用のルール関数はない。違いが生まれる所は3つ。

1. シナリオに書いた**数値の上書き**（`overrides`）。処理の間だけ balance.js の値を差し替える（`withStage`）。
2. シナリオの**データ**。構える味方、敵の動き、増援、敵だけの魔法、③だけの `ex`。
3. その印を見て**分かれる所**（`s.ex`・`s.stage`・`tutorial.slope` など）。

### 足元の自然について

「足元に自然が発生しない」は、チュートリアルだけの決まりではない。人の足元に自然ができる決まり（`ideas.natureUnderUnits`）は、どこでも同じに効く。

- チュートリアルで足元に山ができないのは、使っている魔法が「山」（盛る）だから。山は生きている人のマスには盛らず、その人が倒れたら盛る。
- 本編の「土」も、生きている人の足元には山を盛らない（倒れても盛らない）。
- 水たまり・小さな炎・森は、どちらでも足元にできる。

### 3つに共通の、画面の違い

- 読み込んだとき、説明をログに出さない。
- 読み込み・リセット・やり直しのとき、最初から味方を選んだ状態で始まる。
- 目標をお題の帯に出す。
- 負けたら「やり直す」が出る。2回目からはヒントの1行が出る（文が入っているのは②だけ）。
- 会話の窓が出る（同じ場面は1回の挑戦で1度だけ）。
- 勝ち負けの文は texts.js から取る。今は空なので、ルールの文が出る。

### 本編の中にある違い

ラボ用シナリオを読むと、ターンの形が「1人ずつ」に切り替わる。その中で一斉を選び直したときだけ、一斉のままになる。

## 三つめ：ターンの流れ

```
戦闘の始め：構える味方が構える → 敵が1体ずつ「動く → 向く → 予告」
┌ 味方の手番（順番は自由）
│   選ぶ → 移動先を決める（まだ動かない）→ 向き → 撃つ／構える／待機（ここで移動と行動が一度に決まる）
│   一斉　 ：構えた時点で移動は済み、魔法はまだ。全員が構えるか待機すると「発動」が押せる
│   1人ずつ：撃った瞬間に起きる。全員が行動すると自動でターン終了
├ 構えの発動（一斉）：構えた順に1人ずつ撃つ。構える味方はいつも最後
│   （1人ずつのときは、構える味方だけがここで撃つ）
├ 敵の魔法：予告した敵が撃つ
├ 「1マスずつ進む」敵が進んで撃つ → 馬車が1マス進む
├ ターン終了の処理：燃え移り → 炎の上・火傷のダメージ → 燃え尽き → 小さな炎・花びら・風・火の渦が消える
├ 防衛の勝ち判定 → 外した回数を数える → 増援 → ③の湧きとヒント
└ 次のターン：行動済みを戻す → 構える味方が構える → 敵が「動く → 向く → 予告」
```

### 各段の細かいところ

- **選ぶ**: クリックか1〜3キー。構える味方は選べない。行動済みの味方は選べない（一斉のときは構え直しで選べる）。
- **移動**: 緑のマスをクリックすると予定に入るだけで、盤面にはまだ入らない。移動は2マスまで。泥沼・丘に入るとそこで止まる。
- **撃つ・構える・待機**: 1回の操作で「移動 → 向き → 撃つ／構える／待機」がまとめて決まる。
- **撃つ位置と向き**: 味方の構えも敵の予告も、撃つのは発動した瞬間の位置と向きから。発動までに風で押されれば、形も一緒にずれる。倒れた者の構えや予告は消える。
- **一斉の決まり**:
  - 構えた味方をもう一度選ぶと、向きだけ変えて構え直せる。移動はできず、順番はそのまま。
  - 待機すると構えは消える。
  - ▲▼で発動の順番を入れ替えられる。
  - 予測は、構えた全員を順に発動したときの結果を通しで出す。
  - 違う味方の魔法がつながって決め手が起きると、「合体！」と印が付く。
  - 発動は1人ずつ0.9秒あけて見せる。
- **1人ずつの決まり**: T を押せば、全員が行動していなくてもターンを終えられる。一斉のときは、全員が構えるか待機するまで「発動」は押せない。
- **敵の手の選び方**: 移動できるマスと4つの向きを全部試し、自分や仲間を巻き込む手は選ばない。残りから狙い（人数・近い人・自然・的）で選ぶ。突進の敵は予告を出さず、ターンの始めに走る。

### 移動先を決めただけで撃っていない味方がいて、他の味方を選んだとき

移動先は「予定」として持っているだけで、盤面には入っていない。別の味方を選ぶと**予定は捨てられ、最初の味方は元の位置のまま、未行動に戻る。** 一斉でも1人ずつでも同じ処理（`select()` が予定を作り直す）。

ブラウザで確かめた結果: P1 の移動先を (1,4) にしてから P2 を選ぶと、P1 は (1,5) のまま未行動だった。

「待機」で移動だけを確定させた場合は、その味方は行動済みになる。

- 一斉のとき: 選び直して、その場で構えられる（移動はできない）。ブラウザでも確かめた（待機で (1,4) へ → 選び直すと動けるマスは (1,4) だけ → 構えると「発動 1番目」）。
- 1人ずつのとき: 選び直せず、「もう行動しました」と出る。
