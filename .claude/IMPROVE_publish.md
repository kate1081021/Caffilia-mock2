# IMPROVE_publish — ブラウザで遊べる公開と調整パネル

今の標準（IMPROVE_mission まで）に足す変更。ルールは変えない。
細かい決めごとは `DECISIONS.md`。

## 目的

- **claude.ai を使っていない人にも、URLを開くだけで遊んでもらう。** アカウントもインストールも要らない形にする。
- **リンクを知っている人だけが開ける形にする。** 公開先は Cloudflare Pages（無料）。中身は GitHub の **private** リポジトリに置き、Cloudflare と連携して push で自動公開する。ソース・設計メモは誰にも見えず、サイトは推測しにくいURLでだけ開ける。
  - 「リンクを知っている人だけ」は、URLを合言葉にする仕組み。URLを知った人は開けるし、転送もできる。パスワードで止めるものではない。
- URLは2種類にする。
  - **最新版** `…/latest/` : 作業のたびに上書きする。
  - **固定版** `…/<版の名前>/` : 人に渡す用。一度出したら上書きしない。感想と版がずれないようにするため。
- 遊ぶ人が **手触り（数値）を画面でいじれる** ようにし、いじった設定を **送り返してもらえる** ようにする。

## 進め方のルール

- **今回は私（オーナー）がそばにいる。** GitHub へのログインなど、私の操作が要るところでは止まって、何をすればいいかを短く伝える。それ以外は質問せずに進める。
- 外部ライブラリ・ビルドは使わない。`npm install` もしない。`index.html` をダブルクリックで開いて動く（file://）ことは今までどおり守る。
- 決めたことは `DECISIONS.md` に「公開:」として1行ずつ書く。

## 1. 公開のしくみ

### 1-1. 公開用のリポジトリ

- `git` と `gh`（GitHub CLI）が使えるか確かめる。`gh` がなければ、私の了承を取ってから `winget install GitHub.cli` で入れる。
- `gh auth status` でログインを確かめる。未ログインなら `gh auth login` を私にやってもらう（ブラウザでの承認が要るため）。
- 公開用リポジトリ `caffilia-mock`【仮】を **private** で作る。GitHub Pages は使わない。
- リポジトリは、このフォルダの中の **`publish/`** に clone する。`publish/` はこのモックとは別の git リポジトリとして扱い、モック側の `.gitignore` に `publish/` を足す。

### 1-1b. Cloudflare Pages との連携（最初の1回だけ）

ここは私（オーナー）の操作が要る。Claude は手順と入力する値を短く伝えて止まる。

1. 私が Cloudflare のアカウントを作る（無料プラン）。
2. ダッシュボードで「Workers & Pages → 作成 → Pages → Git に接続」。GitHub の許可画面では **`caffilia-mock` だけ** にアクセスを許す。
3. 設定する値（Claude が伝える）:
   - プロジェクト名: `caffilia-jkwzvlbc7`（オーナーが決めた）。これがそのまま `https://<プロジェクト名>.pages.dev` になる。
   - 本番ブランチ: `main`
   - フレームワーク: なし／ビルドコマンド: 空／出力ディレクトリ: `/`
4. 公開されたURLを Claude に伝える（Claude はそれを `tools/publish.js` の設定に書く）。

- `main` 以外のブランチは push しない（Cloudflare が別URLのプレビューを作ってしまうため）。

### 1-2. 公開するもの・しないもの

- 公開するのは **遊ぶのに要るファイルだけ**: `index.html`・`style.css`・遊ぶのに読み込む `.js`（`balance.js`・`rules.js`・`ui.js` など）。
- **公開しない**: `.claude/`、`*.md`（仕様・報告・メモ）、`tests/`、`v1/` `v2/` などのバックアップ、`publish/` 自身。
  - リポジトリは private でも、公開したサイトのファイルはURLを知る人なら誰でも読める。設計メモを出さないことを優先する。
- **検索に載せない**: 公開する HTML すべてに `<meta name="robots" content="noindex, nofollow">` を入れる。`publish/robots.txt`（全部 Disallow）と `publish/_headers`（全ページに `X-Robots-Tag: noindex`）も置く。
- トップ（`publish/index.html`）は、リンクを知っている人向けの入口として作る。外部サイトへのリンクや、作者が分かる情報は置かない。

### 1-3. 公開コマンド

`node tools/publish.js <版の名前>` で公開できるようにする。

- `latest` を指定したら、`publish/latest/` を上書きする。
- それ以外の名前（例: `1006`）は固定版。`publish/<名前>/` に置く。**同じ名前がもうあれば止まる**（上書きしない）。
- 名前を省略したら、今日の日付 `MMDD` を固定版の名前にする【仮】。
- 公開するときに `version.js` を作って一緒に置く（中身は版の名前と公開日時）。画面はこれを読んで版の名前を出す（2-5）。このフォルダで直接開いたときは「手元」と出す。
- `publish/index.html`（トップ）を作り直す。最新版へのリンクと、固定版の一覧（新しい順）を並べるだけの簡単なページ。
- 最後に commit と `main` への push までやって、公開URLを表示する（Cloudflare が push を受けて1分ほどで公開する）。

最初の公開として、今の状態を `latest` と固定版の両方に出す。

## 2. 調整パネル

### 2-1. 中身

- 画面の横に **「調整」パネル** を足す（開閉できる。最初は閉じておく）。
- `balance.js` の設定にある **数値と true/false を全部、自動で並べる**。項目を手で書き写さない（`balance.js` に項目が増えても、そのままパネルに出るように）。
- 上の階層ごとにまとまりを分けて見出しを付ける。
- よく触る項目を上にまとめる【仮】: HP・移動・威力、炎（強い炎・弱い炎・火傷・燃え尽き）、決め手のダメージ、お題の数値。
- 項目名は日本語のラベルを付ける。対応表は1か所にまとめ、ラベルのない項目は元の名前をそのまま出す。
- 盤面サイズは調整パネルに入れない（エディットに今あるので、そちらで変える）。

### 2-2. 反映のしかた

- 値を変えても、その場では反映しない。**「反映してやり直す」** ボタンで、今のシナリオを最初からやり直して反映する（戦闘の途中で数値が変わって状態が壊れるのを避ける）。
- 初期値から変えた項目は色を変え、初期値を横に小さく出す。
- 項目ごとに初期値へ戻せる。「全部初期値に戻す」ボタンも付ける。
- 変えた設定は localStorage に保存し、次に開いたときも続きから遊べる（使えない環境でも落ちないように try/catch）。
- 初期値から1つでも変えているあいだは、画面の上に **「調整した設定で遊んでいます（N項目）」** と出す。感想が初期値のものか調整後のものか分かるようにするため。

### 2-3. 送り返してもらう形

- **「設定を書き出す」** ボタン: 次の内容をテキストにしてコピーする。
  - 版の名前
  - 遊んでいたシナリオの名前
  - **初期値から変えた項目だけ**（項目名・初期値・変えた値）
  - ひとこと欄（パネルに入力欄を付ける。空でもよい）
  - 読み込み用のデータ（下の 2-4 で貼り付けられる形）
- 見た目は、チャットにそのまま貼って人が読める形にする。読み込み用のデータは最後の1行にまとめる。
- コピーが使えない環境（file:// など）では、テキストを選択した状態の欄に出して、手でコピーできるようにする。

### 2-4. 設定を受け取る形

- **「設定を読み込む」** ボタン: 書き出したテキストをまるごと貼ると、その設定がパネルに入る（反映はボタンで）。
- **共有リンク**: 「この設定のリンクをコピー」で、今の版のURLの後ろに設定を付けたリンクを作る（`#tune=…`）。開くと、その設定がパネルに入った状態で始まる。「リンクの設定で遊んでいます」と出し、localStorage の設定は上書きしない（遊ぶ人が「この設定を保存」を押したときだけ保存する）。
- 読み込んだ設定に、今の `balance.js` にない項目があれば無視し、無視した項目を画面に出す（版が違って項目が変わったとき用）。

### 2-5. 版の表示

- 画面の隅に版の名前を常に出す（例: 「版 1006」）。書き出すテキストにも入る。

## 3. はじめての人向け

- 初めて開いた人に、短い **「遊び方」** を出す（閉じられる。閉じたら次からは出さない。あとからボタンで開ける）。
- 中身は5行くらい: 何をするゲームか（魔法を撃つと自然になる → 重ねると変わる → 壊して敵ごと吹き飛ばす）、味方を選んで動いて向きを決めて撃つ、紫は敵の予告、お題の勝ち方は画面の上、調整パネルで数値をいじれる。
- 最初に開くシナリオは、遊び方が分かりやすいもの【仮】（「燃え広がり」など）にする。

## 4. 作りの決めごと

- 数値の置き場所は `balance.js` 1か所のまま。調整パネルは「`balance.js` の初期値 ＋ 変えた分」を重ねて使う。`balance.js` のファイル自体は書き換えない。
- 重ねる処理と、共有リンク・書き出しテキストの変換は、画面に依存しない関数にして node でテストできるようにする（新しいファイルを作ってよい）。
- `rules.js` は変えない。

## 確かめること

- `node tests/run.js` と `node tests/scenarios.js` がすべて通る（ルールは変えていないので、結果は今までと同じ）。
- テストを足す: 初期値に変えた分を重ねる／変えた項目だけを取り出す／書き出し → 読み込みで元に戻る／共有リンクの変換 → 戻しで元に戻る／ない項目は無視される。
- `node tools/publish.js` で: 固定版の上書きを止める／公開するものに `.claude/`・`*.md`・`tests/`・バックアップが入っていない。
- 公開したURLを内蔵ブラウザで開き、最新版と固定版が動くこと、トップに一覧が出ること、調整 → 反映 → 書き出し → 別のタブで共有リンクを開く、の流れが通ることを見る。コンソールエラーなし。
- このフォルダで `index.html` を直接開いても今までどおり動くこと。

## 終わったら

- `DECISIONS.md` に「公開:」として決めたことを足す。
- `REPORT.md` に今回の報告を足す。次の3つを必ず入れる:
  - 公開URL（トップ・最新版・固定版）
  - これからの公開のしかた（最新版を更新するとき、固定版を出すときのコマンド）
  - 遊ぶ人に渡すときの一文の見本（URLと「調整したら『設定を書き出す』で送ってね」くらい）

## やらないこと

- ルール・数値の初期値を変える。
- スマホ向けの操作（PCのブラウザで遊べればよい）。
- 遊ぶ人の設定を自動で集めるしくみ（サーバー・フォームなど）。送り返しは書き出したテキストか共有リンクを手で送ってもらう。
