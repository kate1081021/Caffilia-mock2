# シナジーの途中を見せる — 洗い出し（11/16）

シナジーと時間で変わるものについて、`game/rules.js` の中で何がどの順で起きているか、出来事（events）に順番・起点・広がる向きが入っているかをまとめた。
ルールは変えずに、画面（`game/ui.js`）だけで途中を再生できるかを確かめるための調べもの。仕様書（`.claude/IMPROVE_vN.md`）の前の段。

確かめ方: コードを読んだうえで、小さな盤面を node で組み、一斉発動（`turnMode: 'simul'`）で `endTurn` の `steps` と `events` を出した。

## 結論

- **画面だけで途中を再生できる。** 起点（`origin`）はどのシナジーの出来事にも入っている。ただし「順番（何歩目か）」が入っているのは凍結と川だけ。ほかは、出来事のマスと前の盤面から画面で計算して出す。
- **一番の壁は、盤面が「1発に1枚」しかないこと。** 1発の中で起きた連鎖（風 → 燃え広がり → 山に届いて火山）は、最後の盤面1枚にまとめて出てくる。途中の盤面は、前の盤面と後ろの盤面の差から画面で組み立て直す必要がある。
- 画面だけで埋めると「推測」になる所が少しある（下の「足りない情報」）。どれも、結果を変えずに出来事に情報を足すだけで確かになる。そこまでやるかはオーナーが決める。

## 1. 今の再生のしくみ

| どこ | 何をしている |
|---|---|
| `rules.js` `endTurn` | 処理しながら `step()` を呼ぶたびに、その時点の盤面の複製と出来事を `steps` に積む |
| `rules.js` `fireStances` | 構えた順に1人ずつ撃ち、**1発ごとに `step()`**。敵も1体ずつ `step()` |
| `rules.js` `shoot` | 1発の中身（移動・押し出し・決め手・連鎖・ダメージ・倒れる）を全部済ませてから戻る。中では `step()` を呼ばない |
| `ui.js` `play` → `nextStep` | `steps` を1つずつ出す。盤面を**その step の最後の盤面に描き直してから**、演出を重ねる。間は 構えの発動 0.9秒（`simul.fireDelayMs`）・ほか 0.4秒（`stepDelayMs`）・③はシナジーで +0.7秒 |
| `ui.js` `showEvents` | 決め手の名前（banner）を**描き直しと同時に**出す。光らせる・⚡・❄・花びら・盛り上がり（`fxGrow`）は、描き直したあとの盤面の上に、波の遅れ（70〜90ミリ秒ずつ）をつけて重ねる |
| `ui.js` `skipPlayback` | 残りの step を全部飛ばして最後の盤面へ。キー（Shift 以外）・1手戻す・リセットなどで呼ばれる。**盤面のクリックでは飛ばさない**（IMPROVE_controls 2章で外した） |

「きっかけと結果が同時に見える」のは、盤面が先に最後の形になり、波の演出はその上をなぞっているだけだから。凍結・川（`fxGrow`）は波の順番を持っているが、マスはもう全部変わっている。

## 2. 1発の中で起きる順番

`shoot` の中はいつもこの順。出来事の並びもこの順になる。

1. `cast`（撃った）… 出来事は最初に置かれるが、文とマスは1発が終わってから埋まる
2. 魔法そのものの作用（置く・点ける・流れる・吹き抜ける）。風で運ばれた人の `push`、泥沼の `mud` もここ
3. 決め手 `finisher`（燃え広がり・桜吹雪・感電・凍結・センタクキ…）
4. 決め手から続く連鎖（燃え広がりが山に届く → `kindle` 火山）
5. ダメージ `damage` → 火傷 `burnStatus` → 倒れた `death` → 決着 `result`（`applyHits`。1発の中で1人1回、一番大きいもの）

ダメージは1発の最後にまとめて出る。波がその人に届いた時点ではない。

## 3. シナジーごと

表の「出来事にある」は、出来事にそのまま入っているもの。「画面で出す」は、前の盤面・後ろの盤面・出来事のマスから計算して出すもの。

### 燃え広がり（炎に風）＋ 山に届いて火山

rules.js の順（`blow` → `doSpread` → `doFunka`）:

1. 風が術者の向きへ吹き抜ける。通り道の人を遠い方から風下へ1マス運ぶ（`push`）。炎か小さな炎に当たったら止まる（そこが起点）
2. 起点から風下へ最大3マス、まっすぐ進む（通り道）。山・川・火山などで止まる
3. 通り道に森があれば、その森とつながった森を全部集める
4. 一度に変える: 通り道の空き → 小さな炎、氷 → 水たまり、集めた森 → 炎
5. 通り道の先が山なら、山脈ごと火山（`kindle`）
6. 燃えた森の上の人に 20、起点と通り道の人に 5 ＋ 火傷

| | 出来事にある | 画面で出す |
|---|---|---|
| きっかけ | `origin`（風が当たった炎）、`dir` | — |
| 通り道 | **ない**（`cells` の先頭に混ざっている。長さは文の「〜へNマス走り」だけ） | `origin` から `dir` へ並ぶマスを `cells` の2番目から拾う |
| 燃えた森 | `strong`（集めた順。近い順ではない） | 通り道の森から、燃えた森の中を幅優先でたどって歩数を出す |
| 火山 | `kindle` の `origin`（届いた山）と `cells`（山脈） | 山脈の中を幅優先でたどって歩数を出す。燃え広がりが通り道の端に着いたあとに置く |

注意: 通り道の先（4マス目）に、通り道の森とつながった森があると、`cells` だけでは通り道と森の区別があいまいになる。

### 山に火 → 火山（山脈ごと）

`placeOrIgnite` → `doFunka`。火が当たった山から、つながった山を幅優先で集め、一度に火山にする（溶岩は今は切）。

- 出来事にある: `kindle` の `origin`（火が当たった山）、`cells`（幅優先の順）
- ない: 何歩目か（`doFunka` の中で `dist` を数えているが、出来事に出していない）
- 画面で出す: `cells` の中を `origin` から幅優先でたどる

### 山に水 → 川

`flow` → `slopeRivers` → `runRiver`（向きごとに1本）。

1. 水が正面の山に当たる（当たったマスが起点）
2. 斜面なら下りの1方向、頂上なら上・右・下・左の4方向
3. それぞれ、山肌を越えて（山のまま）ふもとへ。ふもとから先を川にしながら盤の端まで。人の足元も川にして流れ続ける。村は押し流す（壊れる）。炎は消して止まる。ほかの自然・トロッコの手前で止まる

| | 出来事にある | 画面で出す |
|---|---|---|
| きっかけ | `cast.grows[].origin`（当たった山） | — |
| 順番 | `grows` が向きごとに1つ。`wave` はふもとから 0, 1, 2…（向きどうしは同時） | — |
| 向き | ない | `cells` の並びから出せる |
| 山肌を下る所 | **ない**（越えた山のマスは記録されない） | 前の盤面の斜面（`R.mountainSlopes`）から出せる。省いてふもとから始めてもよい |
| 止まった理由・消した炎 | 文だけ。消した炎のマスは `grows` に入らない | 前後の盤面の差 |
| 押し流した村 | 1発の最後の `damage`・`death` | 村のマスに川が届いた歩数に合わせる |

今も `fxGrow` が `wave` で盛り上がりを出しているが、川のマスは最初から全部描かれている。

### 桜吹雪（火山に風）

標準は `doEruption`（`eruption.scale` 入・`toEdge` 切）。`doSakuraStorm`（盤の奥まで）は今は使っていない。

1. 風が火山に当たる（起点）
2. つながった火山を集める。扇は火山の幅から始まり、風下へ1段ごとに左右へ1マス広がる。火山の一番先から3段先まで
3. 一度に: 扇の人に 20、扇の空きに花びら、火山 → 山に戻る

| | 出来事にある | 画面で出す |
|---|---|---|
| きっかけ | `origin`、`dir` | — |
| 段 | **ない**（`cells` は段の順に並んでいるが、段の番号はない） | `origin` と `dir` から、向きに沿った距離で段を出す |
| 吹き上がる火山 | **ない**（`doSakuraStorm` には `source` があるが、標準の方にはない） | 前後の盤面の差（火山 → 山） |

### 感電（雷が水に落ちる。試しの魔法）

`strike` → `doShock`。つながった水（川・水たまり）を集め、その上と隣の人に一度に 20。

- 出来事にある: `origin`（雷が落ちた水）、`cells`（つながった水。深さ優先の順）
- ない: 何歩目か
- 画面で出す: `cells` の中を `origin` から幅優先でたどる。隣の人は、隣の水に届いた歩数で当てる

### 凍結（冷気が水に触れる。試しの魔法）

`chill` → `doFreeze`。つながった水を幅優先で集め、一度に氷にする。水の上の人は足が凍りつく（`mud` の出来事。`finisher` より前に出る）。

- 出来事にある: `origin`、`cells`、`wave`（幅優先の歩数）。**一番そろっている**
- 今も `fxFreeze` が `wave` で ❄ を出しているが、氷は最初から全部描かれている

### 火の渦・センタクキ（同時に起きるもの。試し）

- 火の渦（吹いている風に火）: 2×2 を選んで一度に火の渦にする。出来事に `origin`・`center`・`cells`・`strong`
- センタクキ（火の渦に水）: 渦と、まわりの輪の人に 20 → 輪の中身（自然と人）を時計回りに輪の長さの4分の1ずらす → 渦は空きに戻る
  - 出来事にある: `origin`（水が当たった渦）、`center`、`cells`（渦＋輪）、人は `push` の `from`・`to`
  - ない: 輪のどのマスがどこへ動いたか（自然の動き）。人の `push` は、今の画面ではまっすぐすべる
  - ダメージの位置は、回したあとの位置で出る（当たった時点の位置ではない）
- 火炎竜巻・オバケヤシキも同じ形（`origin`・`center`・`cells`）

「きっかけのマスを一瞬見せてから一斉に変える」なら、今の情報で足りる。輪が回る様子まで見せるなら、輪の動きが足りない。

### 創造の小さな変化（1マス）

森に火で炎・土で泥沼・水たまりに火で蜃気楼・炎に土で山・風が川の水を運ぶ・水辺の森が隣へ広がる・足元に盛り上がった山から押し出される・氷の上を滑る。
どれも `cast` の中で起きる。決め手の出来事はなく、変わったマスは前後の盤面の差で分かる。押し出し・滑りは `push` に `from`・`to` がある。
押し出し（足元の山）は「形のマスを全部置いたあと」に起きる。

## 4. 時間で変わるもの（ターン終了）

`timePasses`。**ここはもう段ごとに `step()` が分かれている**（0.4秒ずつ出る）。

| 段 | 起きること | 出来事 | 起点・順番 |
|---|---|---|---|
| 1 | 炎が隣の森へ燃え移る（始めの盤面で同時に決める） | `fireSpread`（`cells`） | 同時。どの炎から移ったかはない（前の盤面の隣から出せる） |
| 2 | 炎の上 2・火山の隣と上 2（熱）・火傷 2 → 倒れる | `damage`（`src`: `burn`・`heat`・`burnStatus`）→ `death` | 同時 |
| 3 | 炎が燃え尽きる | `burnOut`（`cells`） | 同時 |
| 4 | 小さな炎が消える・花びらが散る・風／強風がやむ・火の渦が解けて炎になる | 下の注意 | 同時 |

注意: 段4の出来事の種類が使い回されている。花びら・風・強風も `smallfireOut`、火の渦が解けるのは `fireSpread`。見分けるには文を見るしかない。

時間の変化は、どれも「同時に決まる」作りなので、1マスずつ進める必要はない。見せるなら「起点の炎 → 移った森」を一拍で。

## 5. 足りない情報

ルールの結果（盤面）は変えずに、出来事に情報を足せば確かになるもの。画面だけで埋めるなら、右の方法で推測する。

| 足りないもの | 困る所 | 画面だけで埋めるなら | rules.js で足すなら |
|---|---|---|---|
| **1発の中の途中の盤面** | 連鎖（燃え広がり → 火山、水 → センタクキ）が1枚にまとまる | 前の盤面と後ろの盤面の差を、出来事のマスごとに割り当て、順に塗る | 出来事ごとに `changes: [[x, y, 前, 後]]` |
| 燃え広がりの通り道と歩数 | 通り道と森の区別（端のケース）・森が燃え移る順 | `origin`・`dir` から通り道を拾い、森は幅優先 | `path` と `wave` |
| 火山化・感電・桜吹雪の歩数／段 | 1マスずつ進められない | 幅優先、桜吹雪は向きに沿った距離 | `wave`（火山化は `dist` が中にもうある） |
| 桜吹雪で吹き上がる火山 | 火山 → 山の戻りの場所 | 前後の差 | `source`（`doSakuraStorm` と同じ） |
| ダメージが当たったマス | 波が届いた時に数字を出したい。センタクキは回したあとの位置になる | 人の今の位置で合わせる（センタクキだけずれる） | `addHit` が受け取っている `cell` を残す（今は捨てている） |
| 川が山肌を下る所 | 起点の山からふもとまでが見えない | 前の盤面の斜面から出す | `grows` に越えた山のマスを足す |
| センタクキの輪の動き | 回る様子 | なし（同時に変えるなら要らない） | 輪の並びとずらす数 |
| 段4の出来事の種類 | 花びら・風・火の渦を見分けたい | 文で見分ける | 種類を分ける |

足すと、`tests/snapshot.js` のように出来事をまるごと比べるテストは差が出る（今もすべて記録と違うので、記録の取り直しと一緒になる）。

## 6. 見せ方の考えに対して、気づいたこと

- **飛ばす手段が、展示のタッチにはない。** 今はキーで全部飛ばせるが、盤面のクリックで飛ばすのは IMPROVE_controls（10/31）で外した。展示でタッチだけのとき、途中を見せる時間が長くなると、待つしかない。飛ばし方（どこを押すか・ターン全体か今のシナジーだけか）は決める必要がある。
- **決め手の名前（banner）が、今はきっかけと同時に出る。** 一拍置くなら、名前は広がりのあと（か途中）に動かすことになる。連鎖の名前つなぎ（「燃え広がり → 火山！」）も同じ。
- **ダメージの数字と倒れる駒も、1発の最後にまとまっている。** 波が届いた所で出すには、上の「当たったマス」の割り当てが要る。
- **敵の魔法も同じ道を通る**（`shoot`）。敵のシナジーも同じ見せ方になる（柱1「法則に例外はない」と合う）。
- 予測（構えたときの見通し `previewStance`）は `steps` を使わないので、影響しない。
- 1マスずつ塗るたびに盤面を描き直す。つながった森・水を1枚の絵で描く（`fx.bigPicture`）や、奥行きの見た目の山のかたまりは、途中の形で描き直される。6×6 なら重さは問題ない見込みだが、途中の形の絵が不自然でないかは見て確かめる。
- テンポの目安: 燃え広がり（通り道3＋森の歩数2〜3）を1マス 0.09秒で進めると、きっかけの一拍を入れても1〜1.5秒ほど。今の構えの間（0.9秒）より少し長くなる。
