# IMPROVE_mission — お題（防衛・護衛・奪取）

今の標準（IMPROVE_enemy・IMPROVE_fire のあと）に足す変更。
細かい決めごとは `DECISIONS.md`、シナジーの一覧は `SYNERGIES.md`。

## 目的

- 「敵を全滅させる」以外の勝ち方（お題）を3つ足して、**環境を作りながらお題をこなす**手触りを見る。
- 確かめたいのは、**敵のいないところに撃つ理由**が、教えなくても盤面から出てくるかどうか。
  - 防衛: 村の前に壁を立てる
  - 護衛: 馬車の通り道を作る・ふさぐ
  - 奪取: 帰り道で、追ってくる敵の前に壁を作る
- **作り込まない。** まず動かして遊び、違和感はあとで直す。数値と配置は全部【仮】。迷ったら一番シンプルな形を選び、`DECISIONS.md` に「お題:」として書く。

## 大前提

- **盤面に最初から置く自然は、魔法で作れるものだけ。** 今ある自然（森・山・川・炎・水たまり・氷・泥沼 など）以外の特別な地形は作らない。
- 村・馬車・宝は自然ではなく「守るもの・運ぶもの」。下に書く決めごと以外は、ユニットと同じ法則に従う（直撃も決め手も炎の上の2も受ける。味方の魔法でも壊れる）。

## 変えること

### 1. お題をシナリオに持たせる

- 状態に `mission` を足す。種類は `annihilate`（今までどおり敵の全滅）・`defense`・`escort`・`retrieve`。
- 勝敗の判定はお題ごとに分ける。どのお題でも、味方が全員倒れたら負け。
- 画面の上か横に、お題の名前・勝ち方・負け方・残りの数（ターン、村の数、ゴールまでの歩数 など）を常に出す。
- JSON の保存・読み込みに `mission` を含める。エディットでお題の種類と、各お題の置きもの（村・馬車・ゴール・宝・帰り口）を置けるようにする。

### 2. 防衛

- **村**: 1マスを占める置きもの。HP【仮】1。動かない（風で押されない・引き寄せられない）。通れない。
- 勝ち: 【仮】5ターン目のターン終了処理が終わったとき、村が残っている。または敵が全滅する。
- 負け: 村が【仮】1つでも壊れる（`balance.js` の `mission.defense.loseAt`）。
- 駒は「村」の1文字と HP。敵の予告で村に当たるときは、村にも「予告 -N」を出す。

### 3. 護衛

- **馬車**: 1マスを占める置きもの。HP【仮】3。風で押される・引き寄せられる（ユニットと同じ）。
- 盤面に **ゴール**（1マス以上、印を付ける）。馬車がゴールに入ったら勝ち。馬車が壊れたら負け。
- 馬車は、敵の魔法の発動のあと（ターン終了処理の前）に、**ゴールまでの一番短い道に沿って1マス進む**。
  - 道は通れるマスだけ。危ない所（敵の「避」と同じもの）は通らない。ユニットのいるマスも通らない。
  - 道がなければ、その場で待つ。
- 盤面に、馬車の次の1マス（矢印）と、ゴールまでの道筋（薄い線）を常に出す。味方の予測を出しているあいだは、撃ったあとの盤面で計算し直す（敵の予告と同じ扱い）。
- 道筋が固定ではないので、山や川で馬車の道を変えられる。逆に、自分の作った自然で馬車が止まることもある。

### 4. 奪取

- 盤面に **宝**（1マス、敵側）と **帰り口**（味方側の段、印を付ける）を置く。
- 味方が宝のマスで移動を終えると、宝を持つ。**持っている味方は撃てない**（待機だけ）【仮】。移動はふつうどおり。
- 持っている味方が帰り口のマスで移動を終えたら勝ち。
- 持っている味方が倒れたら、宝はそのマスに落ちる（ほかの味方が拾える）。敵は宝を拾わない。
- 駒に「宝」の印。

### 5. 敵の狙いに「的」を足す

- 今の狙い（人数／近い人／自然）に **「的」** を足す。お題の的（村・馬車・宝を持っている味方）にダメージが入る手を一番に選び、同じなら人数で選ぶ。
- 当たる手がないときは、一番近い味方ではなく、**一番近い的**へ向かう（宝がまだ拾われていないときは、近い人と同じ）。
- 駒の印は「的」。お題のシナリオでは、敵の半分くらいを「的」、残りを今までの狙いにする【仮】。
- 「巻き込まない」決めごとはそのまま。敵が自分で村や馬車を巻き込むのは問題ない（的なので）。

### 6. 初期シナリオ（配置は【仮】。遊べる形に直してよい）

- **【お題】防衛**: 7×7。下の段に村2つ、味方 草・土・火、敵2体（上の段）。敵の通り道の近くに森を少し置いておく（燃やせば守りにも攻めにもなる見本）。
- **【お題】護衛**: 7×7。左下に馬車、右の端にゴール。真ん中を横切る川に1マスの切れ目。味方 土・水・風、敵2体。
- **【お題】奪取**: 7×7。上の段に宝、下の段が帰り口。宝のまわりに敵2体、敵側に森か山を少し置く。味方 草・火・風。

## 確かめること

- `node tests/run.js` と `node tests/scenarios.js` がすべて通る。テストを足す:
  - 防衛: 村が直撃・決め手・炎の上の2で壊れる／味方の決め手でも壊れる／5ターンしのいで勝ち／敵の全滅でも勝ち／風で押されない
  - 護衛: 馬車が一番短い道で1マス進む／危ない所とユニットを避ける／道がなければ待つ／山で道が変わる／ゴールで勝ち／壊れたら負け／風で押される
  - 奪取: 移動を終えたマスで宝を持つ／持っている間は撃てない／倒れたら宝が落ちて拾える／帰り口で勝ち
  - 敵の「的」: 的に当たる手を選ぶ／当たらないときは的へ向かう
- `tests/scenarios.js` に、各お題を勝ち切る手順を1つずつ（探索でも手で組んでもよい）。
- `tests/playtest.js` がお題に対応できるなら、勝率を **参考として** 出す。対応が重ければ飛ばしてよい。
- 内蔵ブラウザで3つのお題を最後まで遊び、勝ち方・負け方・残りの数・馬車の道筋・村への予告が画面で分かるかを見る。

## REPORT に書いてほしいこと（設計者向け。遠慮なく）

- 敵のいないところに撃つ手が、お題ごとに自然に出てきたか。出なかったなら何が足りないか。
- お題ごとに、作る自然・壊す自然が変わったか。どのお題でも同じ手（森 → 火 → 風）になっていないか。
- 自分の決め手で村や馬車を巻き込みそうになる場面があったか。それが緊張になっているか、ただ面倒か。
- 敵が作る自然が、邪魔として効いているか、材料として効いているか、どちらにもなっていないか。
- 最初から置いた自然（森・山）が、見本として使われたか。
- 馬車の道が自分の自然でふさがって困る、が起きたか。
- 違和感のあったところ。

## 終わったら

- `DECISIONS.md` に「お題:」として決めたことを足す（【仮】の数値・配置をどうしたかも）。
- `REPORT.md` に今回の報告を足す。

## やらないこと

- 敵を強くする（数・HP・大きさ・速さ）。
- 新しい魔法・新しい自然を足す。
- お題をまたぐ進行（お題の結果を次へ持ち越す、強化の方向を変える など）。
