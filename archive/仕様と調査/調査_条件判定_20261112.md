## 0. 先にまとめ

- **勝ち負けの条件は、ぜんぶコードに直接書かれている。** ステージのデータが持つのは「どの決まりを使うか（`mission` の名前・`ex` があるか）」と、その数値（守るターン数・ゴールのマスなど）だけ。条件そのものを書く場所はデータにない。
- データに条件らしいものが書かれているのは2か所だけ。③のミッション（`ex.missions: [{ id, tile }]` ＝「この自然が盤面にある」）と、あと一手のヒント（`balance.js` の `nextHints`）。
- 判定は全部で **6種類のお題の勝ち負け（14本）＋ 自動クリア1本 ＋ ミッション1本 ＋ ヒント4本 ＋ 文のきっかけ13種 ＋ 画面の進行6本**。下の一覧のとおり。
- 部品にするとき気をつける所は大きく4つ（詳しくは 7章）。
  1. **「このとき誰かが倒れた」をきっかけにしている判定が多い**（盤面の状態だけでは決まらない）。
  2. **判定するタイミングが条件ごとに違う**（撃ったあと・移動を終えたとき・ターン終了処理のあと・いつでも）。
  3. **「道がつながっているか」が4通りある**（通れるマスの決まりがそれぞれ違う）。
  4. **数えを覚えている判定がある**（壊れた村の数・外した回数・山がないまま過ぎたターン数・やり直した回数・一度言ったか）。

## 1. ステージのデータはいま何を持っているか

ステージの定義（`rules.js` の `PRESETS`・`TUTORIALS`、エディットで作るステージ、`stages/*.json`）で、条件に関わるのは次だけ。

| データの項目 | 意味 | 条件そのものか |
|---|---|---|
| `mission`（`'defense'`・`'escort'`・`'retrieve'`。なければ全滅） | どの勝ち負けの決まりを使うか | いいえ（名前で選ぶだけ） |
| `ex` があるか | ボスの決まり（A9・A10）を使うか | いいえ（あるかないか） |
| `overrides['mission.defense.turns']` | 防衛で守るターン数 | 数値だけ |
| `villages`・`wagon`・`goal`・`exit`・`treasure` | 村・トロッコ・ゴール・帰り口・宝の位置 | 位置だけ |
| `spawn` | 増援の出てくる所（B1 の出発点にもなる） | 位置だけ |
| `ex.missions: [{ id, tile, name }]` | ミッション（C1） | **はい**（「この自然がある」だけ書ける） |
| 味方の `npc: true` | 構える味方（A3・D3 が働く） | いいえ |
| 敵の `stand`（`rush`・`boss`・`float` など） | 敵の動き方（A9・B1 が見る） | いいえ |

- エディットの「勝ち方」は5つから選ぶ（`stages_io.js:29` の `WINS`: 全滅・ボス・村を守る・トロッコ・宝）。`stages_io.js:25` に「ルールにある勝ち負けの決まりから選ぶ（新しい決まりは作らない）」とある。
- `stages/草からはじめる.json` の12ステージは、全滅が8、防衛が4（守るターン数 3 か 4）。条件を独自に書いたステージはない。
- `tools/stages20.js:8` に「② ③ ⑭（ここを作ったら勝ち）はまだ決めていない」とある。**「この自然を作ったら勝ち」は、いまの決まりでは書けない勝ち方**（C1 はミッションの達成で、勝ちにはならない）。

## 2. 勝ち負け（A）

勝ち負けを決める所は4か所。

| 場所 | 呼ばれるとき |
|---|---|
| `checkResult`（`rules.js:481`） | ダメージを当てたあと（`applyHits` `rules.js:453`。魔法1発ごと・体当たり）／トロッコが1マス進んだあと（`rules.js:2611`）／ターン終了処理のダメージのあと（`rules.js:2696`） |
| `arrive`（`rules.js:1842`） | 味方が自分で移動を終えたとき（`act` `rules.js:1902`・`move` `rules.js:1938`） |
| `endTurn` の 4b（`rules.js:2776`） | ターン終了処理が終わったあと |
| `claimSeal`（`rules.js:2370`） | プレイヤーが「クリアする」を押したとき（B1） |

`checkResult` の中は上から順に見て、最初に当てはまったもので決まる（**負けを先に見る**。同じ1発で村が壊れて敵が全滅しても負け）。順番は A10 → A9 → A3 → A2 → A4 → A7 → A6 → A1。

### A1. 敵を全員倒したら勝ち
- 使う所: お題が「全滅」と「防衛」（`rules.js:503`）。護衛・奪取では、敵を全滅させても勝ちにならない。
- 置き場所: コード。
- 見ているもの: 敵の数が0、**かつ、このとき敵が倒れた**（出来事の中に敵の death がある）。
- 注意: 「敵が0体」だけでは勝たない。最初から敵がいないステージは、いつまでも勝ちにならない。

### A2. 動かせる味方が全員倒れたら負け
- 使う所: 全お題（`rules.js:494`）。
- 見ているもの: 構える味方を除いた味方の数が0、**かつ、このとき味方が倒れた**。構える味方だけ残っていても負け。

### A3. 構える味方が倒れたら負け
- 使う所: 構える味方（`npc`）のいるステージ（①、草04 など）。`rules.js:492`。
- 見ているもの: **このとき構える味方が倒れた**（出来事だけ。盤面の数は見ていない）。

### A4. 村が決まった数壊れたら負け
- 使う所: 防衛（`rules.js:495`）。
- 置き場所: コード。数は `balance.js:52` の `mission.defense.loseAt`（いまは 1）。
- 見ているもの: **壊れた村の数え**（`s.mission.lost`。村が壊れるたびに1増える。`rules.js:462`）。いまの村の数ではなく、数えを見ている。
- 村は敵の体当たり・炎の燃え移り・味方の魔法のどれでも壊れ、どれも数える。

### A5. 決まったターンまで村が残れば勝ち
- 使う所: 防衛（`rules.js:2776`）。②は5ターン、草08・13・16 は3ターン、草11 は4ターン。
- 置き場所: コード。ターン数は `mission.defense.turns`（ステージの `overrides` で上書き）。
- 見ているもの: いまのターン数が決まった数以上、かつ村が1つ以上ある。
- タイミング: **ターン終了処理（燃え移り・火傷など）が終わったあとだけ**。増援と、次のターンの敵の移動（突進の体当たり）より前。
- 重複: 同じ式が予測（`forecast` `rules.js:3054` の `held`）にもう1つある。勝ち方の文（`missionInfo` `rules.js:3660`）にも手で書いてある。

### A6. トロッコがゴールのマスにいたら勝ち
- 使う所: 護衛（`rules.js:499`）。
- 置き場所: コード。ゴールのマスはデータ（`goal`）。
- 見ているもの: トロッコの位置が、ゴールのマスのどれか。
- タイミング: `checkResult` が呼ばれるとき。自分で進んだときも、風で押されて入ったときも（魔法のあとに見るので）勝ち。

### A7. トロッコが壊れたら負け
- 使う所: 護衛（`rules.js:496`）。
- 見ているもの: トロッコが盤面にない、**かつ、このときトロッコが壊れた**。

### A8. 宝を持って帰り口で移動を終えたら勝ち
- 使う所: 奪取（`rules.js:1849`）。
- 置き場所: コード。帰り口のマス・宝の位置はデータ（`exit`・`treasure`）。
- 見ているもの: 宝を持っている味方（`s.mission.carrier`）の位置が、帰り口のマスのどれか。
- タイミング: **味方が自分で移動を終えたときだけ**。風で運ばれて帰り口に入っても勝ちにならない（`checkResult` では見ていない）。
- 付いている決まり: 宝のマスで移動を終えると持つ（`rules.js:1845`）／持っている味方は撃てない（`canShoot` `rules.js:1863`）／持っている味方が倒れると宝がそのマスに落ちる（`rules.js:464`）。「誰が持っているか」を覚えている。

### A9. ボスがいなくなったら勝ち
- 使う所: ボスの決まり（ステージに `ex` がある。③）。`rules.js:489`。
- 見ているもの: 動き方が `boss` の敵が0体、**かつ、このとき敵が倒れた**。取り巻きは数えない。

### A10. 味方が1人でも倒れたら負け
- 使う所: ボスの決まり（③）。`rules.js:488`。
- 見ているもの: **このとき味方が倒れた**。
- 画面: 負けたあと 1.8 秒で、ステージの頭から自動でやり直す（F5）。

## 3. 自動クリア（B）

### B1. 村への道をふさぎきったら、その場でクリアにできる
- 何を判定しているか: 突進の敵と増援の出てくる所のどこからも、地形だけで見て、どの村の隣へも行けない。
- 使う所: 防衛。②と、防衛の草08・13・16（突進の敵がいるもの）。`sealReady`・`rushSealed`（`rules.js:2369`・`2378`）。
- 置き場所: コード。入切は `balance.js:52` の `mission.defense.sealWin`（標準で入。ステージごとの上書きは読むときに捨てる `stages_io.js:167`）。
- 見ているもの:
  - お題が防衛、まだ決着していない
  - 村が1つ以上ある
  - **敵が全員、突進の敵**（1体でもほかの動き方の敵がいると、ふさいでも成り立たない）
  - 出発点（敵のいるマス＋増援の出てくる所）が1つ以上ある
  - 経路: 出発点から縦横に、通れる地形で、水たまり・泥沼でなく、村でないマスをたどって、村の隣のマスに着けない
  - **人（味方・敵）は数えない**。味方が道に立っているだけでは、ふさいだことにならない
- タイミング: いつ聞いても同じ答えが出る（盤面だけで決まる）。ただし **勝手には勝たない**。画面に「クリアする」が出て、プレイヤーが押したら勝ち（`claimSeal`。オーナー 10/17）。押さずにターンを続けてもよく、ふさいだままならあとからでも押せる。
- 重複:
  - 画面の3か所が同じ `sealReady` を聞いている（F1 自動のターン終了を止める `ui.js:551`／F2 右下のボタン `ui.js:1046`／案内の行 `ui.js:2045`）。テストの進め方（`tests/scenarios.js:40`）も同じ。
  - 勝ち方の文に「ふさいだらクリアにできる」を足すかどうか（`rules.js:3659`）は、**別の式**（突進の敵が1体でもいるか、増援が突進か）で決めている。B1 本体（敵が全員突進）とずれている。

## 5. ヒントと文のきっかけ（D・E）

### 敵の動き（お題の条件ではないが、盤面を見て決まる）

- 突進の敵: 村の隣まで行ける道があるか。走り終えて村の隣にいたら体当たり（`rushRoute`・`rushMove` `rules.js:2316`・`2399`）。
- 取り巻き: 風の人の隣に来たら体当たりを予告（`floatRoute` `rules.js:2467`）。
- ボス: 体の全部が入れるときだけ前へ進む（`bossStep` `rules.js:2460`）。
- 普通の敵: 狙い（的・人数・近い人・自然）で撃つ先を選ぶ（`planEnemy`）。

### 対象にしなかったもの
- 魔法 → 自然 → シナジー → 決め手の決まり（燃え移り・桜吹雪など）。これは世界の法則で、ステージごとの条件ではないので、洗い出しには入れていない。
- エディットの「置けるか」の確かめ（`stages_io.js` の `fits`・`checkDef`）。

## 7. 重複と、部品の組み合わせでは書きにくそうな所

### 7-1. 同じ判定が別の場所にもある

| 判定 | 本体 | もう1つある場所 |
|---|---|---|
| A5 守り切った | `rules.js:2776` | 予測 `rules.js:3054`（同じ式を書き写し） |
| 勝ち方・負け方ぜんぶ | `checkResult` ほか | 画面に出す文 `missionInfo`（`rules.js:3643`）に、お題ごとに手で書いた文。条件を変えたら文も手で直す |
| B1 を文に書くか | `rushSealed`（敵が全員突進） | `rules.js:3659`（突進の敵が1体でもいる）。**式が違う** |
| どの勝ち方か | `checkResult` の分かれ方（`ex` → お題） | `stages_io.js` の `winOf`（`206`）と `winKind`（`289`）。同じ分け方を2回書いている |
| F1 自動のターン終了 | `ui.js:551` | `tests/scenarios.js:40` |
| 帰り口までの道のり（奪取の残りの表示） | — | `missionInfo` の中に、その場かぎりの経路の計算（`rules.js:3680`） |

### 7-2. 「道がつながっているか」が4通りある

同じ「A から B へ行けるか」でも、通れるマスの決まりが違う。部品を1つにすると、どれかの答えが変わる。

| 使う所 | 通れないもの | 人の扱い |
|---|---|---|
| B1 ふさぎきったか（`rushSealed`） | 通れない地形・水たまり・泥沼・村 | 数えない（いないものとして見る） |
| 突進の敵の道（`rushRoute`） | 通れない地形・水たまり・泥沼 | 通り抜けられるが、止まれない |
| トロッコの道（`wagonRoute`） | 通れない地形・危ない所（炎・小さな炎・泥沼・溶岩） | いるマスは通れない |
| 奪取の残りの表示（`missionInfo`） | 通れない地形だけ | 数えない |

行き先も違う（B1 と突進は「村の隣のマス」、トロッコは「ゴールのマスのどれか」）。出発点も B1 は「敵ぜんぶ＋増援の出る所」と複数ある。

### 7-3. 盤面の状態だけでは決まらないもの

| 判定 | 理由 |
|---|---|
| A1・A2・A7・A9 | 「数が0」だけでなく「**このとき倒れた**」が条件に入っている。いまの盤面を見るだけの部品では、最初から0のステージで動きが変わる（いまは勝ちも負けもしない） |
| A3・A10 | 「このとき倒れた」だけで決まる。盤面の数を見ていない（「構える味方が0人」「味方が最初より少ない」と書き直すと、最初の人数を覚えておく必要がある） |
| A4 | 壊れた村の数えを見ている（「最初の村の数 − いまの村の数」と同じ意味だが、最初の数を覚えておく必要がある） |
| A8 | 「宝を持っている」は盤面のタイルや位置ではなく、誰が持っているかの覚え。しかも「自分で移動を終えたとき」だけ |
| C1 | 一度達成したら、あとで条件が外れても達成のまま |
| D1・D2・D3 | ターン終了のたびに数える数え（通算）と、「もう言った」の覚え。「N ターン続けて」ではなく「通算 N 回」 |
| D4 | やり直した回数。1回の戦闘の外にまたがる |
| E の大半 | 盤面ではなく「出来事が起きた瞬間」（構えた・決め手が起きた・敵が予告した）。`beforeFire` は発動を待たせる |

### 7-4. タイミングが条件ごとに違う

同じ条件でも、いつ聞くかで結果が変わる所。

| 判定 | 聞くとき | 聞かないとき（そのせいで起きること） |
|---|---|---|
| A1〜A4・A6・A7・A9・A10 | ダメージを当てたあと・トロッコが進んだあと・ターン終了処理のあと | 移動しただけ・構えただけのとき |
| A5 | ターン終了処理のあとだけ | 増援・次のターンの敵の移動より前に決まる（最後のターンの終わりの体当たりは起きない） |
| A8 | 味方が自分で移動を終えたとき | 風で運ばれたとき（帰り口に入っても勝たない） |
| B1 | いつでも（画面が描くたび） | 成り立っても自動では勝たない。押したら勝ち |
| C1 | 魔法を1発撃ち終わるたび | ターン終了処理で自然ができたとき（次の1発まで達成にならない） |
| D1〜D3 | ターン終了処理のあと | — |

### 7-5. 負けを先に見る順番

`checkResult` は負け → 勝ちの順に見て、最初の1つで決める。「かつ・または」で勝ちの条件と負けの条件を別々に書くと、**同時に成り立ったときどちらにするか**の決まりが別に要る（いまは負けが勝つ。同じ負け同士では A10 → A3 → A2 → A4 → A7 の順で文が決まる）。

### 7-6. 条件に「ステージの種類」が混ざっている

- A9・A10・C1・D1・D2・取り巻きの湧き方・F5 は、どれも「`ex` があるステージ」という1つの印にまとまっている。ばらばらには選べない（ボスを倒す勝ち方だけ使って、味方が1人倒れても続ける、はいまできない）。
- A3・D3 は「構える味方がいる」と自動で付く。ステージからは外せない。
- A2（味方が全員倒れたら負け）はどのお題にも必ず付く。
- A1（全滅で勝ち）は防衛にも付くが、護衛・奪取には付かない。
