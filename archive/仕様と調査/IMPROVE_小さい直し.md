## 1-1. 戻るボタンで展示モードに戻らない

**オーナー:** 戻るボタンで開発モードから展示モードに戻ってしまうのは何とかならないか？
**決めたこと:** 開発モードのまま、1つ前の画面に戻る（テストプレイ → エディット → 開発の最初の画面）。

**今:** 開発モードの中で画面を変えても、ブラウザの履歴には何も積まない。だから「戻る」を押すと、`#dev` の付いていない前のページ（展示モード）へ戻る。`game/mode.js` の `hashchange` が読み込み直して、展示モードで開く。

**作り:**

- 開発モードでは、画面を変えるたびに `history.pushState` で履歴に積む。URL は今のまま（`#dev` を残す。hash が変わらないので `hashchange` は起きない）。
- `popstate` で、積んだ1つ前の画面をアプリの中で出す（読み込み直さない）。
- 積む画面: 開発の最初の画面／エディット（どのステージか）／テストプレイ（どのステージか）。`game/ui.js` の `showHome` と、エディット ⇄ テストプレイの切り替え（E）が入口。
- 「1手戻す」（Z・`app.history`）とは別のもの。混ぜない。
- 開発の最初の画面が一番下。そこで「戻る」を押しても開発モードのまま、その場に残る。開発の最初の画面に入ったときに、最初の画面の履歴をもう1つ積んでおけばよい。開発モードから出るのは、今までどおり右下の点の2秒長押しだけ。
- 展示モードの「戻る」は今回は変えない。

**確かめ:** `#dev` → ステージを遊ぶ → E でエディット → 「戻る」を3回押す。テストプレイ → 開発の最初の画面 → 最初の画面のまま、と1つずつ戻り、展示モードにならない。`serve.js` と file:// の両方で確かめる。docs は `画面構成.md` の「2つのモード」に1行足す。

## 1-2. 「村を守る」と「道をふさぐ」を1つに

**オーナー:** 村を守る＝道をふさぐ、これは同じ。
**決めたこと:** 勝ち方は「村を守る」1つ。決まったターンまで守るか、村への道をふさいだら「クリアする」でクリア。

**今:** エディットの勝ち方に「村を守る（決めたターンまで）」と「道をふさぐ（ふさいだらクリアにできる）」の2つがある（`game/stages_io.js` の `WINS` の `defense` と `seal`）。違いは overrides の `mission.defense.sealWin` だけ。標準（`game/balance.js` の `mission.defense.sealWin`）は false で、② だけ overrides で true にしている。

**作り:**

- `balance.js` の `mission.defense.sealWin` を true にする（防衛ならいつも、ふさいだらクリアにできる）。② の overrides の `sealWin: true` は要らなくなる（外す）。
- `stages_io.js`: `WINS` から `seal` を外す。`defense` の名前を「村を守る（決めたターンまで守るか、道をふさいだらクリア）」に。
  - 前の JSON・自分のステージ・みんなのステージで `seal` や `sealWin: false` になっているものは、読み込むと「村を守る」として扱う（`sealWin` の上書きは捨てる）。書き出しに `sealWin` を書かない。
- 突進の敵も増援もいない防衛のステージで、何もしないうちに「ふさいだ」にならないこと（すぐに「クリアする」が出ないこと）を確かめる（`rules.js` の `rushSealed`・`sealReady`）。なってしまうなら、突進の敵か増援がいるときだけ、ふさいだ判定をする。
- 勝ち方の文を1つに（`rules.js` の勝ち方の説明 `info.win`、`texts.js` にあればそこも）。
- tests: `tests/stages.js`（勝ち方の読み書き・前の `seal` が読めること）、`tests/run.js` の防衛まわり。
- docs: `遊び方.md` の「勝ち方」の表と下の注、`画面構成.md` のエディットの勝ち方。

## 1-3. 炎は消えない・村も燃える

**オーナー:** 森が燃えたら次のターンに炎が消えるのはなぜ？ 消えないで。ターン終了で隣に燃え移るのはいいかな、村も燃えるようにしようか。炎は消えない。

**決めたこと:**

- 炎（強い炎）は燃え尽きない。消えるのは水か土を当てたときだけ（今のまま）。
- 小さな炎（空きに火・燃え広がりの通り道）は今どおり、ターン終了で消える（マッチの火）。
- 村は燃える。燃えるのは次の3つのとき。燃えた村は壊れ、そのマスは炎になる（そこからまた隣の森・村へ燃え移る）。
  - ターン終了に、隣の炎から燃え移る
  - 燃え広がりの通り道にある
  - 火の魔法を直接当てる
- 法則の1文: 村は木でできていて、森と同じく、火が点くと燃える。
- 敵の炎でも同じ（法則に例外はない）。
- 結果として、森は時間がたつと全部燃え、炎が盤面に残り続ける（炎の上でターン終了すると2）。これでいい。

**作り:**

- `balance.js` の `fire.burnOutTurns` を 0 にし、0 は「燃え尽きない」とする。`rules.js` の `timePasses` の 2c（`burnOutCells`）で、0 なら何もしない。炎の年齢（`s.fireAge`）も、0 のときは数えなくてよい。【育つ】の `grassBurnOut` は切ってあるので触らない。
- 燃え移り（`fireSpreadCells`）: 隣の炎から、森と同じく村のマスにも燃え移る。村は壊れ（川が押し流すときと同じ数え方。`rules.js` の村が壊れたときの `m.lost`）、マスは炎になる。出来事の文は「炎が村に燃え移った」。森と同じく、ターン終了の始めの盤面で同時に決める。
- 燃え広がり: 通り道に村があれば燃える（壊れて炎）。そのあと止まるか先へ走るかは、森を通るときと同じにする（作る前に、今の燃え広がりが森の上をどう走るかを確かめて合わせる）。
- 火の魔法を村に当てる: 今は直撃（村の HP 1 が減って壊れる）。これを「点けて燃える」（壊れてマスが炎）にする。直撃のダメージと二重に数えない。
- 防衛で村が燃えたら、押し流されたときと同じく数える（`mission.defense.loseAt`）。
- 盤面の予告（次のターン終了で何がどこへ燃え移るか）に、村への燃え移りも出す（CLAUDE.md 3章「見える」）。
- tests:
  - 燃え尽きを期待しているものを直す（`tests/run.js` の燃え尽き、`rules.js` のシナリオで「炎の列は2回目のターン終了で燃え尽き、敵Bが出てくる」もの など）。シナリオの筋が燃え尽きに頼っているものは、今の動きが法則どおりか確かめてから期待か筋を直す。筋を変えるときはオーナーに一言伝える。
  - 足すテスト: 炎が3ターン目も残る／小さな炎は今どおり消える／村が隣の炎からターン終了に燃える／燃え広がりの通り道の村が燃える／火を村に当てると炎になる／敵の炎でも同じ／燃えた村のマスからまた隣の森へ燃え移る。
- ①（森・火・風）を遊んで、結果が変わらないか見る（燃え尽きる前に決着しているはず）。
- docs: `自然と魔法とシナジー.md`（自然の表の炎の行・魔法 × 自然の表に村の行・「時間で変わるもの」の 3）、`遊び方.md`（「ターン終了」の並び・ダメージ）。
