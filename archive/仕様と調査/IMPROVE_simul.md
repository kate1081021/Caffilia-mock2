# IMPROVE_simul — 一斉発動で遊ぶ・チュートリアル3つ・文章を自分で書けるようにする

10/17 の展示に向けた作業。ターンの形を「構えて、ターンの終わりに一斉に発動」に切り替えられるようにし、チュートリアル3つをその形で遊べるようにする。チュートリアルには物語の文章を持たせ、文章はオーナーが画面の中で書き換えて保存できるようにする。

一斉発動と今の形（1人ずつ撃つ）のどちらが良いかは、まだ決まっていない。この作業の目的は、両方を同じ盤面で遊びくらべられるようにすること。

---

## 0. 進め方のルール

- 質問しない。止まらない。あいまいな所は一番シンプルな解釈を選び、`DECISIONS.md` に「一斉:」として1行ずつ書く。
- 外部ライブラリ・ビルド・ネットは使わない。`index.html` を開けば動く（file://）まま。テストは node だけ。
- 数値・配置・仮の文は全部【仮】。

## 1. 大前提

1. **展示を壊さない。**
   - main から `simul` ブランチを作り、その上だけで作業する。main にはまだ入れない（オーナーが遊んで決めてから入れる）。lab ブランチには触らない。
   - 公開するときは固定版 `simul-MMDD` だけ（`node tools/publish.js simul-MMDD`）。`latest` は更新しない。
2. **「1人ずつ」にすれば今の展示と同じ。** `node tests/run.js`・`node tests/scenarios.js` は「1人ずつ」で今までどおり全部通る。
3. **持ってくるのは一斉発動だけ。** ラボのほかの案（人の足元にも自然、育つ、強化など）は持ってこない。
4. **起こした本人が巻き込まれるかの決まりは変えない。** チュートリアルの配置で避ける。

## 2. ターンの形を切り替える

- 上のバーに「ターンの形: 一斉に発動 ／ 1人ずつ」。初期値は一斉に発動。選んだ形は localStorage に覚える（読み書きは try/catch）。チュートリアル・シナリオ・デモ、どれも両方の形で遊べる。
- 一斉発動の中身は、lab ブランチにある「構えて、ターンの終わりに一斉に発動（合体技）」（`balance.js` の `lab.F5`、処理は `lab_rules.js`）を持ってくる。ルールは同じ。
  - 1ターンの流れ: 敵の移動と予告 → 味方の構え（3人。誰からでもよい） → 味方の構えを、構えた順に発動 → 敵の発動 → ターン終了
  - 手番では移動と構え（立ち位置・向き・魔法）。構えはまだ起きず、味方の予告として盤面に出し続ける
  - そのターンのうちなら構え直せる（移動は戻らない）。構えた順も並べ替えられる
  - 予測は「構えた順に全部起きたあと」の盤面で出す。敵の予告の結果も、その盤面で計算し直す
- 判定のときのオーナーのコメントから足すこと。
  - 構えの印は、敵の予告と同じくらいはっきり出す（色だけ変える）。どのマスに何が当たるかが一目で分かること
  - 構えの印に発動の順番の番号を付ける。並べ替えは、盤面の横の一覧で▲▼（スマホでも押せる大きさ）
  - 発動は1人ずつ間をあけて順に見せる。決め手が起きたら名前を出し、続けて次の決め手が起きたら名前を続けて出す（「燃え広がり → オバケヤシキ！」）
  - 違う味方の魔法がつながって決め手が起きたら「合体！」と、参加した味方を並べて出す
  - 「発動」ボタンは、3人が構え終えたら押せる。押す前ならいつでも構え直せる
- 「1人ずつ」は今のまま。

## 3. チュートリアル

3つとも、チュートリアルの一覧から順に遊べる。どちらのターンの形でもクリアできること。

### ①「重ねる」（動かすのは1人）

- 今のものをそのまま使い、一斉発動でも遊べるようにする。
- 一斉発動のとき: 仲間（自分では動かせない）は最初から風を構えていて、その構えが盤面に出ている。仲間の順番は最後に固定（並べ替えの一覧でも動かせない）。自分が火を構えて発動すると、「自分の火 → 仲間の風」で燃え広がり。
- 外したとき、発動の流れで「火は点いたのに、風は別の所を吹いた」と見えるかどうかを `REPORT.md` に書く。

### ②「2人で守る」（動かすのは2人）

- 今のもの（横5・縦11、十字の山、水は高い所から低い所へ）をそのまま使う。
- 一斉発動のとき: 山と水の2人が構え、構えの番号で順番が分かる。山 → 水で川の壁、水 → 山だと泥沼。順番を入れ替えると結果が変わることが、予測で分かる。
- 負けてやり直すときのヒントは、ターンの形ごとに分ける（例: 一斉発動なら「順番を入れ替えると…？」【仮】）。

### ③「3人で合わせる」（新しく作る。動かすのは3人）

- 見せ場。3人の構えが盤面に並び、発動で一気に3段目まで流れて「合体！」。
- 味方: 土・草・風。決め手: 桜吹雪（土で山 → 草で桜 → 風で桜吹雪）【仮】。main にある桜の決まり（草が山に当たると桜）を使う。main になければ `DECISIONS.md` に書いて、main にある一番近い3段目にする。
- 盤面は小さめ（6×6〜8×8）。敵は2〜3体、動いて予告する。
- 1ターン目に3人で合わせれば勝てる配置にする。外しても2ターン目に立て直せる（1回のミスで負けにしない）。
- 3人とも、自分たちの桜吹雪の扇に入らない位置から起こせること。
- 1人ずつでも、同じ順に撃てばクリアできる。
- デモ（いちばん良い手順）を1つ付ける。

## 4. シナリオの文章

チュートリアル（とステージ）に、物語の文章を持たせる。**文の中身はオーナーが打ち込む。** Claude Code は、文が出る「場所」と、操作が分かる最低限の仮の文だけを作る。

### 4-1. 文の置き場所

- 画面に出る文章を `texts.js` に1つにまとめる（file:// で読めるよう、`window.TEXTS = {...}` の形）。
- 入れるもの: チュートリアルとステージの名前・目標・シナリオの文・ヒント・クリアと負けの文、決め手の表示名、「合体！」などの表示、展示で遊ぶ人が読む操作の案内。
- 決め手の内部の名前（ルールが使うキー）は変えない。`texts.js` に持つのは表示名だけ。
- コードの中に、遊ぶ人が読む日本語の文を直接書かない（`texts.js` から読む）。

### 4-2. シナリオの文の形

- ステージごとに、「きっかけ」ごとの文の並びを持つ。
  - きっかけ: ステージの始め／Nターン目の始め／構えたとき（魔法を指定できる）／発動の前／決め手が起きたとき（名前を指定できる）／敵が予告したとき／クリア／負け／やり直し
- 1行は「話す人（名前。空でもよい）」と「文」。ターンの形の指定（両方／一斉だけ／1人ずつだけ）を付けられる。
- 画面の下に会話の窓を出し、話す人の名前と文を出す。押す（クリックかスペース）と次の文へ。窓が出ている間も盤面は見える。
- 仮の文は、何をすればいいかが分かる1文だけ（例:「火を構えて、発動を押そう【仮】」）。物語・口調・キャラクターの名前は書かない。物語の文の欄は「（ここに文章）」にしておく。

### 4-3. 画面の中で書き換える

- 上のバーに「文章」ボタン。押すと、調整パネルと同じ作りで左から開く。
  - ステージ → きっかけ → 文の一覧。文ごとに、話す人と文を書き換えられる。行の追加・削除・並べ替え（▲▼）。ターンの形の指定も変えられる。
  - 「この場面を流す」で、その きっかけ の文をその場で流して確かめられる。
  - 目標・ヒント・決め手の表示名・操作の案内なども、同じパネルで書き換えられる。
- 会話の窓の端に小さな ✎。押すと、今出ている文をその場で書き換えられる。
- 書き換えは、すぐにゲームに反映する。

### 4-4. 保存

書き換えた内容を、そのまま `texts.js` に保存できるようにする。

- 「保存」ボタン: ブラウザのファイル保存の機能（File System Access API）が使えるときは、最初の1回だけリポジトリの `texts.js` を選び、以後は押すだけで上書き保存。
- 使えない環境（スマホ、Chrome 以外、公開版）では、新しい `texts.js` をダウンロードする。オーナーがリポジトリの `texts.js` と入れ替える。
- 「書き出す」: 書き換えた所だけを、チャットに貼れるテキストで出す（コピーボタン付き）。
- 保存する前の書き換えは localStorage にも残す（try/catch。閉じても消えないように）。保存していない書き換えがあるときは、上のバーに「未保存」と出す。「書き換えを捨てる」で `texts.js` の内容に戻せる。
- `texts.js` に保存した日時を持たせる。`texts.js` のほうが新しいのに古い書き換えが localStorage に残っているときは、`texts.js` を優先し、残っていた書き換えは「書き出す」で見られるようにする（黙って上書きしない）。

## 5. くらべるための記録

どちらの形が良いかを決める材料。オーナーが気にしているのは「パズルっぽさが上がるか」「関係ないところに撃つ、がやりにくくなるか」。

- `tests/playtest.js` か探索で、今あるシナリオを両方の形で回し、`REPORT.md` に数字を書く（重ければ飛ばし、その旨を書く）。
  - 決め手が初めて敵に入ったターン
  - 1ターンで3段目まで通した回数
  - 敵から3マス以上離れたマスに自然を作った手の割合（関係ないところに撃つ）
  - 味方が倒れた数
- 作ってみて気づいたこと（両方の形で遊んだときの違い、分かりにくい所）を、褒め言葉より事実で書く。

## 6. 終わったら

- 3つのチュートリアルを、両方のターンの形でクリアできることを確かめる（テストにも足す）。
- 文章パネルで文を書き換え → 会話の窓に出る → 保存 → 読み込み直しても残っている、を確かめる。保存の機能が使えない環境ではダウンロードになることも確かめる。
- 内蔵ブラウザで、構えの印・番号・並べ替え・発動の流れ・会話の窓・文章パネルを確かめる。スマホの幅でも押せるか。コンソールエラーなし。
- 「1人ずつ」で `run.js`・`scenarios.js` が今までどおり全部通る。
- `REPORT.md`・`DECISIONS.md`・`PROGRESS.md` を更新する。

## 7. やらないこと

- main・lab に入れる、`latest` を公開する
- 一斉発動以外のラボの案を持ってくる
- 本人が巻き込まれない決まりを足す（配置で避ける）
- 1ターンで消えるもの（風・小さな炎・花びら）の扱いを変える（ラボで別に試す）
- 物語の文・キャラクターの名前・口調を書く（オーナーが打ち込む）
