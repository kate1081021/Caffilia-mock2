## 1. 書き方

ステージの定義（`rows`・`allies`・`enemies` と同じ並び）に、3つ足す。

```json
{
  "name": "…", "rows": ["…"], "allies": ["…"], "enemies": ["…"],

  "template": "defense",
  "counters": { "数えの名前": { "…": "…" } },
  "conditions": [
    { "id": "…", "when": ["…"], "if": { "…": "…" }, "then": "win", "text": "…", "done": "…" }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `template` | どのひな形から作ったか（`annihilate`・`defense`・`escort`・`retrieve`・`boss`）。一覧の区分（戦闘・ボス・防衛…）に使う札。条件そのものは `conditions` に展開して持つ |
| `counters` | 数え（1-4） |
| `conditions` | 条件の並び。**並び順が、同時に成り立ったときの優先順**（1-5） |

### 1-1. 1つの条件

| 項目 | 中身 |
|---|---|
| `id` | 名前（テスト・画面が指す。ステージの中で重ならない） |
| `when` | いつ見るか。下の5つから。複数なら並べる |
| `if` | 何を見るか（1-2・1-3） |
| `then` | `"win"` 勝ち／`"lose"` 負け／`"canClear"` クリアできるようにする（ボタンを出す）／`"mission"` ミッション達成 |
| `once` | `true` なら一度だけ（成り立ったら覚えて、もう見ない）。`mission` で使う |
| `text` | 説明の文。画面の勝ち方・負け方・ミッションの欄は、ここから出す |
| `done` | 成り立ったときの文（「敵を全員倒した！（勝利）」）。なければ `text` |

`when` の名前:

| 名前 | いつ | 今のコード |
|---|---|---|
| `afterDamage` | ダメージを当てたあと・トロッコが進んだあと・ターン終了処理のダメージのあと | `checkResult` が呼ばれる所 |
| `turnEnd` | ターン終了処理が終わったあと（増援・次のターンの敵の移動より前） | `endTurn` の 4b |
| `allyMoved` | 味方が自分で移動を終えたとき | `arrive` |
| `afterShot` | 魔法を1発撃ち終わるたび（敵の魔法も） | `exMissions` を呼ぶ所 |
| `always` | いつ聞いても（盤面だけで決まる）。`canClear` 専用 | `sealReady` |

### 1-2. 部品（`if` に書くもの）

どれも `{ "see": 部品の名前, … }`。数をくらべるのは `min`（以上）・`max`（以下）・`eq`（ちょうど）。

| `see` | 何を見るか | 書き方 |
|---|---|---|
| `units` | 絞ったユニットの数 | `{ "see": "units", "where": 絞り方, "eq": 0 }` |
| `unitIn` | 絞ったユニットが、マスのどれかにいるか | `{ "see": "unitIn", "where": 絞り方, "cells": "goal" }` |
| `tiles` | タイルの種類と数。`in` を付けると、そのマスの中だけ | `{ "see": "tiles", "tile": "volcano", "min": 1 }` |
| `turn` | ターン数 | `{ "see": "turn", "min": 5 }` |
| `died` | このとき、絞ったユニットが倒れた・壊れた | `{ "see": "died", "where": 絞り方 }` |
| `counter` | 数え | `{ "see": "counter", "name": "lostVillages", "min": 1 }` |
| `path` | 道がつながっているか | 1-3 |

組み合わせ: `{ "all": [ … ] }` かつ／`{ "any": [ … ] }` または／`{ "not": … }` ではない。

絞り方（`where`）。書いた項目をぜんぶ満たすユニット:

| 項目 | 値 |
|---|---|
| `side` | `"ally"`・`"enemy"`・`"object"` |
| `kind` | `"village"`・`"wagon"` |
| `stand` | 敵の動き方（`"rush"`・`"boss"`・`"float"`・`"march"`・`"still"`・`"move"`） |
| `npc` | `true` 構える味方／`false` 動かせる味方 |
| `magic` | 魔法の名前 |
| `carrying` | `true` 宝を持っている |
| `not` | 中の絞り方に当てはまらないもの（`{ "side": "enemy", "not": { "stand": "rush" } }` ＝ 突進でない敵） |

マス（`cells`・`in`）: `"goal"`・`"exit"`（今のデータのゴール・帰り口）か、`[[x, y], …]`。

- 「村の数」は `units` で `kind: "village"`。「宝を持った味方の位置」は `unitIn` で `carrying: true`。「ある位置のタイル」は `tiles` に `in`。部品を別に作らなくて済む。
- **`died` の「このとき」**: その1回の操作（1手、またはターン終了のひとまとまり）の中で、ここまでに倒れたもの。今のコードと同じ数え方。

### 1-3. 道

```json
{ "see": "path",
  "from": [ { "units": { "side": "enemy" } }, "spawn" ],
  "to":   { "nextTo": { "kind": "village" } },
  "walk": "rush", "people": "ignore",
  "is":   "closed" }
```

| 項目 | 中身 |
|---|---|
| `from` | 出発点の並び。絞ったユニットのいるマス／`"spawn"`（増援の出てくる所）／マス |
| `to` | 行き先。絞ったユニットの隣（`nextTo`）／マス（`cells`） |
| `walk` | 通り方の名前。`"rush"` ＝ 突進の敵と同じ（通れる地形で、水たまり・泥沼でない）。**敵が動くときと同じ部品を使う**（ずれなくなる） |
| `people` | `"ignore"` 人はいないものとして見る／`"block"` 人のいるマスは通れない |
| `is` | `"open"` どれか1つでも着ける／`"closed"` 出発点が1つ以上あって、どこからも着けない |

`"closed"` は、出発点が1つもないと成り立たない（今の `rushSealed` と同じ）。

### 1-4. 数え

```json
"counters": {
  "lostVillages": { "add": { "see": "died", "where": { "kind": "village" } }, "reset": "never", "keepOnRetry": false }
}
```

| 項目 | 中身 |
|---|---|
| `add` | 何で増えるか。`died` なら倒れた数だけ増える。ほかの部品なら `on`（`when` と同じ名前）のたびに、成り立っていれば1増える |
| `reset` | いつ0に戻すか。`"never"`／条件（成り立ったら0） |
| `keepOnRetry` | やり直しをまたいで残すか |

今回使うのは A4（壊れた村）だけ。`on`・`reset` の条件・`keepOnRetry` は、のちのヒント（D1〜D4）のための枠。

### 1-5. 同時に成り立ったとき

- 同じときに見る条件の中で、**負けが勝ちより先**（今と同じ）。
- 同じ側（負け同士・勝ち同士）は、`conditions` の並び順で先のもの。出る文が決まる。
- 見るときが違えば、先に来たときのものが決まる（今と同じ。`afterDamage` はターン終了処理の中、`turnEnd` はそのあと）。
- 決着したら、もう何も見ない。

## 3. ひな形の中身

エディットの「勝ち方」でひな形を選ぶと、この並びが `conditions` に入る。入ったあとは普通の条件なので、1つずつ外せる・足せる。

| ひな形 | 入る条件（この順） | 数え | 選ぶときに決める数 |
|---|---|---|---|
| `annihilate` 全滅 | A3 → A2 → A1 | — | — |
| `defense` 防衛 | A3 → A2 → A4 → A1 → A5 → B1 | 壊れた村 | 守るターン数（A5 の数と文に入る） |
| `escort` 護衛 | A3 → A2 → A7 → A6 | — | — |
| `retrieve` 奪取 | A3 → A2 → A8 | — | — |
| `boss` ボス | A10 → A9 | — | — |

- 今のコードの順（負けは A10 → A3 → A2 → A4 → A7、勝ちは A9 → A6 → A1）をそのまま並べた。
- A3 は構える味方がいないステージでは一度も成り立たないので、どのひな形にも入れてある（今と同じ）。
- 今は、ボスの決まりのステージでも A1〜A3 が裏で動いているが、A10 と A9 が先に決めるので、結果には出ない。ひな形からは外した。
- 防衛の B1 は、突進でない敵がいるステージでは成り立たないだけなので、いつも入れてある（今と同じ）。

## 4. 画面の文

- 勝ち方の欄: `then` が `win` と `canClear` の条件の `text` を並べる。負け方も同じ（今は負け方を画面に出していないので、出すかは今のまま）。

## 5. 書けない所・書くと動きが変わる所

### 5-1. 「お題」は条件だけでなく、しくみの入切も兼ねている

条件をデータに出しても、次は今のまま `mission` の名前で動いている。

| しくみ | 今の入切 |
|---|---|
| トロッコがターンの終わりに1マス進む | お題が護衛のとき |
| 宝のマスで移動を終えると持つ・持っている間は撃てない・倒れると落とす | お題が奪取のとき |
| 敵の狙い「的」が狙うもの（村・トロッコ・宝を持つ味方） | お題ごと |
| 取り巻きの湧き・③のヒント・負けたら自動でやり直す・発動の出し方の切り替え | `ex` があるとき |

- 「全滅のひな形に A6（トロッコがゴール）を足す」と書いても、トロッコは進まない。
- 条件と揃えるなら、置いてある物で動く形（トロッコとゴールがあれば進む・宝があれば拾える）にする手がある。今回の範囲の外なので、案には入れていない。

### 5-2. ふさぎ（B1）: 地形の決まりは、もう同じだった

読んだかぎり、今の B1 と突進の敵は、通れる地形の決まりが同じ（通れる地形で、水たまり・泥沼でない）。

| | 今の B1 | 突進の敵 |
|---|---|---|
| 地形 | 通れる地形・水たまりと泥沼は不可 | 同じ |
| 村のマス | 通れない | 通り抜けられる |
| 人 | いないものとして見る | 通り抜けられるが、止まれない |
| トロッコ | いないものとして見る | 通れない |

- 村のマスの違いは、答えを変えない（村のマスに入るには、先に村の隣に立つ必要があるので、その時点で「着ける」）。
- 残る違いは人とトロッコだけで、人は今までどおり数えない。**揃えても、今のステージで答えが変わる所はない見込み**。
- 得になるのは、同じ部品（`walk: "rush"`）を敵の動きと条件の両方が使うようになり、あとで突進の決まりを変えても、ずれなくなること。
- 前の調査の 7-2 の表は「村」を違いとして書いていたが、答えには効かない。

### 5-3. A8（奪取）を変えたときの、変わらない所

- 風で運ばれて**帰り口**に入ったら勝ちになる。
- 風で運ばれて**宝のマス**に入っても、宝は拾わない（拾うのは条件ではなく、しくみ。5-1）。ここは今のまま。

### 5-4. 「この自然を作ったら勝ち」は、連鎖の途中で止まる

- `afterShot` は1発ごとに見るので、一斉の発動で、1人目の魔法で成り立ったら、そこで決着して2人目以降は撃たない（今の A1 も同じで、途中で敵が全滅したら止まる）。
- 火山で勝ちにすると、そのあとの桜吹雪は起きない。最後まで見せたいなら、「発動がぜんぶ終わったあと」という見るときが要る（今の5つにはない）。

### 5-5. 残りの数の表示は、条件からは出ない

- 勝ち方の欄の横の「敵 残り2体」「ターン4/5」「ゴールまで3歩」「宝は (3,0) にある」は、お題ごとに手で書いてある（`missionInfo`）。
- `text` からは出せない。今のままお題の名前（`template`）ごとに出すか、部品ごとに出し方を決めるかになる。ひな形から条件を外したステージでは、表示だけ残る。

### 5-6. C1 の見るとき

- 例は今と同じ `afterShot` だけにした（ターン終了処理でできた自然は、次の1発まで達成にならない）。
- 「作ったら勝ち」と揃えて `turnEnd` も足すと、③で達成が出るときが変わることがある。

### 5-7. 古いステージの読みこみ

- 今のステージ（`stages/草からはじめる.json`、ブラウザに保存したもの、みんなのステージ）は `mission`・`overrides['mission.defense.turns']`・`ex` で勝ち方を持っている。読むときに、ひな形に読み替える必要がある。
- `balance.js` から `mission.defense.turns`・`loseAt`・`sealWin` を消すと、今の読みこみの確かめ（`validOverrides`）が「知らない項目」ではじく。消すなら、読み替えを先に通す。

### 5-8. 予測

- 予測（`forecast`）は A5 の式を書き写して、「守り切って終わるなら、増援と突進の予告を出さない」を決めている。移すときは、写しをやめて同じ条件を聞く形にする。動きは変わらない。

## 6. 確かめたい所

1. お題が兼ねているしくみ（5-1）は、今回は `mission` の名前に残したままでよいか。
2. `always` は `canClear` 専用でよいか（勝ち負けを「いつでも」で見ると、演出の途中で決着する）。
3. 「この自然を作ったら勝ち」は、連鎖の途中で止まってよいか（5-4）。
4. C1（③のミッション）の見るときは、今のまま（撃ったあとだけ）か、ターン終了処理のあとも足すか（5-6）。
5. ステージが持つのは、展開した `conditions`（＋札としての `template`）でよいか。ひな形の名前だけを持って、読むたびに展開する形もある（そのときは「1つ外す」を別に書く必要がある）。
6. 残りの数の表示（5-5）は、今回はお題の名前ごとのままでよいか。
7. 項目の名前（`when`・`if`・`then`・`see` など）は英字にした（今のデータの `rows`・`allies` に合わせた）。日本語の名前がよければ変える。
